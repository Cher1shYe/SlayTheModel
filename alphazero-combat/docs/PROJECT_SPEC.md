# 项目规格与验收边界

## 目标

学习一个只负责单人战斗决策的策略：随机种子变化时仍能泛化；以 MCTS 策略分布/访问次数作为监督信号，先用现有 MCTS 轨迹冷启动，再在通过回归的模型上自博弈迭代。完整战斗和经验证合法的战斗中途状态都是训练起点。事件、地图行进、商店、火堆、奖励选择和其他战斗外行为都不在策略范围内。

## 观测与动作契约

策略输入是 `CombatDecisionPoint.Observation` 的严格投影，而不是 `CombatSearchPoint` 或 `CombatSnapshot`。现有协议投影位于 `DecisionObservationProjector.ToCombat()`。其 schema 当前含战斗轮次、己方回合侧、玩家战斗资源与牌堆、遗物/药水/球、双方生物 HP/格挡/力量；不含 RNG、`NativeCardJson`、determinism counters 或未来意图。实现网络适配器时采用 `src/azcombat/schema.py` 的显式 allowlist；新字段默认拒绝，审阅后再升级 schema。

动作 ABI 与游戏协议的动作描述分开版本化。当前公开 `CombatActionDescriptor` 暴露出牌、药水、结束回合和 `ResolveChoice` 结构，但现有公开 capture 不足以证明任意选择/嵌套选择都已连通。不得把这个描述误当作完成的训练 action space。

## 奖励与标签

MCTS 与 `reward.py` 共用同一奖励：终局胜利为 `0.5 + atan((最终HP - 入场HP)/20)/pi`；明确失败为 `-1 + 0.25 * clamp(累计敌方HP损失 / 起始敌方总HP, 0, 1)`；达到深度上限但战斗尚未终结为 `-0.5 + 0.25 * clamp(累计敌方HP损失 / 起始敌方总HP, 0, 1)`。因此任意胜利都优于未完成，未完成的范围 `[-0.5, -0.25]` 高于失败 `[-1, -0.75]`，各自内部按造成的敌方 HP 损失体现进度；胜利内部则按己方净掉血排序。敌方伤害必须使用模拟器累计的实际 HP 损失，不得用当前 HP 差近似，以免复活敌人使进度错误回退。胜/负标签只采用原生模拟器完成死亡结算后的明确终态；超时、取消、模拟异常和丢失证据不计为 rollout，也不赋予学习回报。

## 训练和验收阶段

1. 锁定环境/coverage 清单和数据 schema，按 seed 做 train/validation/未见 holdout 切分，严禁同一 seed 或重放副本跨集合。
2. 校验并导入现有 MCTS 数据；仅纳入能够恢复合法动作集合且动作与状态严格对齐的轨迹。无访问次数的动作选择记录不能冒充策略分布标签。
3. Python 训练 DeepSets+MLP policy/value；报告胜率、胜利时己方掉血、失败时敌方伤害进度、校准和按起点/角色/遭遇分层指标。
4. 候选导出 ONNX，验证输入输出 schema 和数值一致性，再经 NativeWorker adapter 跑 shadow/replay；策略只能返回当前 legal mask 中动作。
5. 通过未见种子配对评估、非法动作率（目标为 0）、嵌套选择/排序/取消回归、死亡结算回归、覆盖边界和性能门槛后，才原子晋级 champion。失败候选隔离保存，不覆盖既有模型。
6. 新 champion 才可产生自博弈样本；每代数据与模型独立留档，并保留可回退 champion。

## 尚未实现的关键接口

- MCTS rollout/sample writer：需要同时记录严格观测、可执行合法动作树、访问统计、实际终局和可复放环境身份。
- Choice bridge：公开决策协议目前没有完整表达多层选择状态；必须补充 adapter/协议但只能放在本目录和新工作器边界内，不能修改核心。
- 合法中途状态生产：checkpoint archive 的恢复/回放工具存在，但它不等价于任意时点训练样本生成器。必须证明选择边界恢复、隐藏状态一致和合法动作一致。
- NativeWorker 推理协议：ONNX 模型输入张量、批量动作评分、版本握手、超时回退及只提交合法动作均待实现。
- 训练/自博弈管线、覆盖准入过滤、全套晋级回归和 100 sims/s 实测均待实现。

因此本目录目前是可测试的安全契约与实施蓝图，不是已经可训练或可部署的 AlphaZero 系统。
