# Step 1 native downgrade fixtures

This isolated host runs 28 controlled cases against the actual installed target game DLL (`v0.111.0 / 41cef1ea`). `validation.json` pins the DLL, harness, and raw-result hashes. No installed game or mod is changed, and the global game scene is not loaded. The source and results from earlier rounds are preserved.

`AuditWorker.cs` records 19 direct `CardCmd.Downgrade` cases and nine event branches (Reflections `TouchAMirror`, Wongo `Leave`, Wongo with no upgraded candidates; seeds 0, 42, and 987654321). Direct cases include canonical/temporary/combat-cap/free costs, X and unplayable costs, keyword restoration, Steady/Vigorous enchantments, replay, and Maul/Thrash/Rampage growth. Growth amounts are placed into the native card's private accumulated-growth field as fixture setup; native downgrade itself is unmodified. The fixture's `Cost` helper records X cost as `-1` and negative unplayable cost as `-2` to distinguish the two in JSON. C++ represents both with `-1` and uses the Unplayable flag to distinguish them; the comparison maps the fixture's `-2` marker back to `-1` and also checks that flag. The initial regression incorrectly compared these representation markers directly; `first-cpp-failure.txt` and `first-cpp-failure-test.cpp.txt` preserve that failure. The raw native results and harness were not changed to fix it.

Event RNG is reset **after** native `BeginEvent` in both implementations. Therefore, this checks branch candidate identities/order, random-call counts, card costs and upgrade state, retained card/enchantment/replay identity, and event completion. It does not certify Wongo's featured-item generation, purchases, or progress behavior. C++ snapshot checks are in `simulator/tests/native_step1_downgrade.cpp`.

The production helper is used for the two deck-event downgrade paths. Existing fields independently represent temporary absolute cost, free combat cost and the Enlightenment combat cap; these are preserved. The engine still lacks a complete ordered local-cost-modifier stack: Snecko's combat absolute modifier and Frantic Escape's relative modifier share `costForTurn`/`storedCost`. General combat downgrade with those modifiers is outside this fix; the helper does not claim to infer their missing provenance. Mad Science's custom configuration also remains outside scope.

Build with `dotnet build SimulatorAudit.csproj --no-restore -c ExportRelease -o .godot/mono/temp/bin/ExportRelease`, copy the resulting `SimulatorAudit.dll` (and PDB) into `SimulatorAudit.app/Contents/Resources/data_SimulatorAudit_macos_arm64/`, sign the copied host with `codesign --force --deep --sign - --entitlements entitlements.plist SimulatorAudit.app`, then run `python3 run_native.py`. The copied local host and its game dependencies are validation dependencies, not distributable source artifacts.
