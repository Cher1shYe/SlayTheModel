# Step 2 native card reward fixtures

This isolated host runs the installed `v0.111.0 / 41cef1ea` game DLL. `validation.json` pins the actual assembly and source/result hashes. No game or mod deployment is performed, and the global game scene is not loaded.

`results.json` contains 82 native effect cases for Lead Paperweight, Arcane Scroll, Dream Catcher, Dusty Tome and Sea Glass configured for each of the five characters. Each setup uses `UnlockState.all`. The source records seeds, ascensions (0 or 7), act index, initial relic ordering, and explicit choices. It exercises normal choices, skip, Sea Glass selecting all 15 cards, and ordered hooks from the three eggs, Fresnel Lens, Wing Charm, Glitter, Silver Crucible, Silken Tress, Dingy Rug and Prismatic Gem. The reward and niche RNG streams are reset only after setup. The inherited host installs its existing UI/runtime compatibility patches, not simulator rule substitutions.

Lead Paperweight and Sea Glass execute native `AfterObtained` with `CardSelectCmd.PushSelector`. Arcane Scroll executes native acquisition. Dusty Tome uses native `SetupForPlayer` before acquisition, retaining the selected identity. Dream Catcher executes the native rest-heal routine; the rewards test selector records all offered cards then explicitly skips the rewards set. A RestSiteRoom is pushed before these calls, so combat-only reward modifiers are not accidentally applied by the fixture's initial combat session.

The C++ test checks candidate identities and order, upgrade/enchantment state, RNG counters, rarity pity, Silver Crucible/Silken Tress use state, and Dusty Tome's preserved setup card. It checks that generation itself never automatically adds cards. Run-level grid pause/resume, selection, skip and snapshot behavior need the separate integration checks; this generator test does not certify UI execution.

`content-metadata.json` is a separate actual-DLL export of all 596 cards and all 12 native pool lists. It includes energy and star costs (including X flags), base/upgraded keywords and variables, native class/model IDs, rarity, type, target, generation eligibility, multiplayer constraint and maximum upgrade level. `characterOrder` confirms Ironclad, Silent, Regent, Necrobinder, Defect. `AuditWorker-metadata.cs.txt` and `metadata-invocation.json` preserve its independent provenance. Metadata matching does not demonstrate complete effect support.

Build with `dotnet build SimulatorAudit.csproj --no-restore -c ExportRelease -o .godot/mono/temp/bin/ExportRelease`, copy the resulting SimulatorAudit DLL/PDB into the copied app's `Contents/Resources/data_SimulatorAudit_macos_arm64/`, sign with the included entitlements, and run `python3 run_native.py`. Local copied executables and game dependencies are validation dependencies, not portable deliverables.
