# 在 SF2 v14 上评估 sh02v17

从仓库根目录构建当前 `sim/` 扩展，并在同一 Python 环境安装 NumPy 和 PyTorch。使用 A9、铁甲战士、直线地图和固定种子 7540000–7540499。每局由模型处理事件、奖励、商店等选择，仅第三幕最终 Boss 进入实战；普通战、精英、前两幕 Boss 和事件战跳过出牌，通过 v14 的胜利结算处理奖励。历史 309/500 的课程保留了事件战。本评估中打开并跳过卡牌奖励会消耗当前奖励槽，其他待领奖励继续可选。

```sh
python sim/build.py
python train/a9/evaluate_a9.py --init /path/to/latest-322-dev100-sh02v17-inference.pt --out results.jsonl --workers 8
```

输出路径须为新文件。可用 `--count 8` 验证前八个种子。脚本校验权重 SHA-256、v14 ruleset 和接口版本；模型使用 CPU 推理，按 `seed * 3001 + step` 采样。最多 3000 个决策，重复公开状态使用原评估的 64 步历史和 16 次命中阈值。每个种子占结果文件一行，含终止原因、最终楼层、实际 Boss 和战斗决策数。胜率以全部指定种子为分母。

## 观测和动作适配

- `adapter.py` 把 v14 的宏观实体、地图边、公开向量和合法动作编码为模型的五个输入张量。模型权重从外部文件严格载入，包括策略和价值头。
- `layout.py` 根据字段重排公开向量：逐卡变换、区分遗物和药水词表、保留 Boss 和地图的位置、分别变换整局和战斗区段。旧记录专有的楼层历史、克隆标记等填零。旧模型只能表示四个怪物实体；v14 的全部合法目标仍参加打分。新增物品保留实体类别，缺少历史词表项时使用空身份。
- 战斗动作按卡牌、药水、目标和选择操作重排为 729 维。宏观动作按含义映射到模型类别，例如“打开升级选择器”和“离开休息点”。新增且没有旧类别的选择使用独立类别。执行时使用对应的 v14 合法动作原值。
- 单选与多选适配位于 `combat_choices`、`grid_choice_rows` 和 `step_policy_action`。必须选一张时，模型选中该牌后由适配层提交 v14 要求的确认。多选时按实际卡牌实例过滤已选项，保留其余可选牌和可用的结束动作。两类附魔的空选择确认不能完成，适配层过滤该无效确认。额外的单选确认不占用一次模型采样或随机种子步数。
- 默认游戏入口继续按原生规则处理卡牌奖励。专用入口 `init_final_boss_evaluation` 和 `step_final_boss_evaluation` 只在当前调用期间对指定局应用课程规则。运行依赖只有 SF2 的模拟器、模型定义及 Python 库。

`a9-final-boss-500.jsonl` 记录允许重开时的逐种子基线，`a9-final-boss-skip-once-500.jsonl` 记录跳过后消耗该奖励槽的评估。


相同 500 个种子重评：跳过后消耗当前卡牌奖励槽，最终 282 胜（56.4%），496 局进入最终 Boss。146 局正常战败，70 局循环截断，2 局触发 v14 的 Finished card identity capacity 上限。奖励及选牌页面的循环从 433 局降至 0 局。模拟器异常单独记录；胜率分母包含全部 500 局。

### Fetch 计数和选牌适配后的复评

同一固定面板（7540000–7540499）仅打最终 Boss，冻结 sh02v17，8 个 CPU worker。Fetch 只登记该牌自身的不同实例；先用原适配器回放 7540124 和 7540316，两局均由容量异常变为正常胜利。加入必选单张的确认、多选去除已选牌和无效空确认后，500 局全部正常终局，351 胜、149 负（70.2%），499 局进入最终 Boss。与跳过奖励槽的基线相比净增 69 胜（13.8 个百分点）；此前 70 局循环现在 45 胜、25 负，2 局容量异常现在均胜。
