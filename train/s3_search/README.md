# sh02v17 参数搜索

在仓库根目录运行。沿用 v14 的 A9 公开观测、动作适配和仅打最终 Boss 的评估配置。候选是实际可加载的 PyTorch 权重，搜索只做推理。需要当前 v14 的 Python 扩展、A9 适配包以及 NumPy、SciPy、PyTorch、filelock。

## 当前实验：每轮一个子候选，四人父代池

首批由 Codex 提出五份不同的 `sh02v17` 子权重，与基线各跑相同的 100 个种子。可用下方校准命令到第 0 轮生成这份输入。已有校准目录也可直接传入，入口只导入前六个权重及其 600 局。正式实验使用独立的新目录。

```powershell
$weight = "$env:USERPROFILE/Downloads/latest-322-dev100-sh02v17-inference.pt"
py -3.14 train/s3_search/live_search.py --weight $weight --calibration train/s3_search/runs/codex50 --run-dir train/s3_search/runs/live50 --rounds 50
```

每轮固定一名新候选与两位保留者进行同种子比较。每次主比较在开始时跳过三者预测全部低于 15% 或全部高于 85% 的种子。比较期间每采纳一条新结果即更新 Rasch 后验，每完成一个共享种子就重新计算其余可用种子的分歧概率，选择下一种子。每个权重和种子组合至多记入一次。并行预取缓存只在该种子被选中时才进入后验。

按桌面《三区组工作流选择：整体机制与定理证明》的比较规则，三方分歧计分、严格或容差停止，必要时按前二概率触发历史候选召回。召回使用完整开发种子域，配对净胜差达到 3 或种子用尽即停止。将保留两位与池外全历史平均后验胜率前二组成四人池，每轮等概率抽一名父代。测试前冻结最后池内四个模型的参数哈希。

- `request-NNN.json` 包含抽中的父代和全部直接子候选的修改方向、当前表现及较弱子代在共同已采纳种子上的退步摘要。Codex 自主决定新方向并提交含 `model`、`model_config`、`direction` 的子权重。进程等待该文件就绪并继续。
- `updates.jsonl` 保存首批之后的逐条采纳顺序；`round-NNN.json` 保存入选者、实际比较种子、召回及停止原因。后验估计针对全部 100 个开发种子，实测胜局和局数只含该候选已采纳的结果。
- `test-selection.json` 和 `test-results.json` 分别保存冻结名单及独立 500 种子的结果。循环、模拟器异常及其他截断计作未胜。

## 首批校准和早期固定面板入口

```powershell
$weight = "$env:USERPROFILE/Downloads/latest-322-dev100-sh02v17-inference.pt"
$run = "train/s3_search/runs/codex-01"
py -3.14 train/s3_search/search.py --manual --weight $weight --run-dir $run --rounds 0
```

1. 读取最新的 `requests-*.json` 中最后一条请求。搜索器按顺序请求候选。父权重来自 `parent_checkpoint`，`parent_feedback.children` 给出该父候选所有已提交的直接子代、各自的修改方向及当前表现。同轮较早提交的兄弟候选也在其中，等待整批评估时 `result` 为 null。
2. Codex 自行决定修改方向，载入父权重、修改副本，将非空文本 `direction` 与 `model`、`model_config` 一起写入请求指定的 `submit` 文件。方向应记录实际修改的参数、改法及想验证的想法。脚本校验方向与权重，并将方向持久化到对应的候选 JSON。
3. 重跑同一命令取得下一条请求。整批候选齐备后才评估，随后刷新后验排名。对于当前后验估计低于父代的每个直接子代，下一次使用该父代的请求会附上 `problem_summary`、父胜子未胜和子胜父未胜的种子，以及父胜子未胜时子代的结束原因和界面。首批校准前只有已提交方向可供参考。逐局结束记录支持现象归纳，具体决策原因需要另行核实。
4. 要继续搜索，在同一运行目录调大 `--rounds`。已完成的候选与种子组合从 SQLite 读取。新版反馈格式使用新运行目录，旧验证记录可直接查看。

默认使用当前 Codex 会话处理请求，启动器不单独调用语言模型 API。显式传入 `--manual` 也使用同一入口。

## 早期固定面板模式的筛选与父代

- 默认首批 6 个候选（含基线）各打同一组 100 个开发种子（8541000–8541099），每个候选和种子组合只打一局。原固定评估集 7540000–7540499 留作独立评估。
- 参考 aflow S3 的 Rasch 与 Laplace 方法，以候选强度减种子难度作为胜率的 logit。基线强度固定为零，种子难度以及子代相对父代的强度差均使用标准差 1.5 的高斯先验。首批实测后拟合，用每个种子在首批候选上的平均预测胜率筛选，保留闭区间 [15%, 85%]。面板随后固定；若为空，本次校准终止。
- 筛后保留难度与候选强度的联合均值、协方差作为后续先验；更新时只加入校准之后的对局。每个候选按保留面板上的平均后验预测胜率排名。循环、步数截断及模拟器异常按原评估口径计为未胜，具体终止原因保存在逐局记录里。
- 从上轮保留者和本轮新候选中保留估计前二，再从所有历史候选中排除这两位，取当前后验排名前二。每个新候选独立、等概率从这四位中抽一位作为父代，同轮可以抽到同一父代。默认每轮 2 个新候选。用 `--initial`、`--children`、`--seeds` 和 `--rng` 可在新运行中调整。
- `calibration.json` 记录逐种子拟合胜率与筛选结果；`round-*.json` 记录保留者、父代池、实测胜局和后验估计；`c*.pt` 与同名 JSON 保存实际候选权重、参数指纹和谱系；`trials.sqlite` 的 `trials.result` 保存逐局结果。开发面板经筛选，其胜率只用于候选比较。
