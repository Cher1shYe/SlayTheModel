## 晋级规则

`network-only-v1`：256 场配对验证中，只要 network 通过原有的干净执行、效用差置信区间、胜率保护条件，就更新共同冠军。search 仍使用 256 simulations、相同配对场景，保存原始数据、胜率、HP、效用、置信区间与分层统计；search 不显著提升或下降均不否决晋级。search 执行异常仍中止并报告，不能掩盖工程故障。

最终模型全部冻结后才运行独立测试。两个 seed 的 network 分别报告增益检验，search 结果单列。历史联合晋级不能事后改称 network-only 训练。

## 距离通用战斗还需要哪些阶段

目标应定义为：支持固定游戏版本中的合法内容，在大量未见组合上，相比可靠基线取得稳定的决策质量。无法要求任何构筑／血量／敌人组合都高胜率，因为其中可能存在无解局面。“能运行”与“打得好”分别验收。

从本次基础继续推进，可按以下 **6 个能力阶段**组织；这是工程路线，不是承诺只需 6 次代码修改或 6 轮训练。

1. **通用卡牌状态与动作**：把目前逐 ID 的白名单扩展为能表示临时费用、升级／变化、生成牌、选牌、保留、X 费、已知牌序与更多能力的统一结构。补齐机制依赖和真实／粒子一致性。
2. **多敌人与完整怪物机制**：可变目标、群攻、召唤、复活、阶段切换、Boss、复杂随机 AI、状态牌。奖励和编码不能再假定只有一个敌人。
3. **遗物与药水交互**：编码计数、一次性触发、战斗开始／结束钩子、持久状态、额外动作；逐机制审核与卡牌／怪物的组合效果。
4. **全角色与固定版本内容闭合**：角色专属资源、所有卡牌／遗物／怪物内容清单、机制级和组合级回归；引擎已有工厂不代表 planner 已支持。多批交付，不能只把 ID 全放进词表。
5. **规模化学习与迁移**：宽分布课程、难例采样、旧场景保留、跨版本权重迁移、提升模拟吞吐和训练容量。按学习曲线决定采样量，避免每加内容都从随机网络重来。
6. **未见组合与实战验收**：在训练之外保留整类构筑、遗物组合、Boss／难度和随机种子；多 seed、足够样本、置信区间、分组弱项和强基线比较。实机接入还需状态读取及动作执行的一致性检查。

第 4 阶段完成才有资格说“内容基本都能跑”；第 6 阶段完成且指标过线才有证据说“广泛组合能打得好”。当前 10 轮只是本批有限内容的训练预算，不能外推通用能力。现有数据不足以负责任地给出总天数或所需训练步数；应在更广覆盖的学习曲线和吞吐测量后估算。若目标还包含选卡、商店、路线和整局通关，需要另外增加战斗外决策阶段。
