# G1.4b 合并批次：X 费、限时整手保留与多选

2026-10-10。按用户要求将多个机制合并实施、统一验证。本批新增 Whirlwind、Purity、Equilibrium 的普通／升级版，共 26 种卡牌。仍为 Ironclad、七种单敌、六家族、126 层，G1 整体尚未完成。

## 已冻结的依赖与机制

规则参考本地 `decompiled/MegaCrit.Sts2.Core.Models.Cards/{Whirlwind,Purity,Equilibrium}.cs` 和 `Models.Powers/RetainHandPower.cs`；引擎参考 `cards/ironclad.py`、`cards/colorless.py`、`core/combat.py`、`core/selection.py`、`powers/turn_effects.py`。本批未修改原生引擎规则。

- **Whirlwind**：X 费支付出牌前全部能量，普通／升级每次伤害 5／8，按支付量重复攻击。零能量仍是合法出牌并触发一次攻击出牌钩子；不是每次命中都再次触发 Stomp 或 Slow。能量上限由初始 3 加最多 400 次决策、每次最多新增／重置 3 推导为 1,203，新版本明确验证此界限，旧版本限制不变。网络编码 X 属性、按当前能量计算的潜在命中数及本回合支付汇总。
- **公开支付记录**：每次正常出牌记录 token 与实际支付量，选择切换／确认不会重复追加或扣费。回合结束清空本回合记录；粒子恢复本回合支付总量。Whirlwind 每次出牌重新支付；旧卡实例上遗留的 `energy_spent` 不影响下一次出牌，不作为持久卡属性存储。当前没有 X 费卡暂停选牌或自动重放，不能据此声称这些尚未开放的续执行已支持。
- **Purity**：保留／消耗，允许选择 0..3／0..5 张手牌。候选保留原生顺序和重复牌位置；点击可选择／取消，达到上限后不能加入新项，但仍可取消已选项。动作 0 在此阶段是确认，允许空选，不结束回合。所有选择在确认前不产生消耗效果；确认后按候选顺序消耗所选牌，再完成 Purity 自身消耗与 after-play。粒子根据公开约束、候选、已选集合重建回调，不读取真实闭包。
- **Equilibrium**：费用 2，格挡 13／16，获得 1 层 RetainHand。多次使用叠加保留回合数，每个玩家回合结束递减；最后一层仍作用于该次弃牌阶段，随后到期。该机制通过临时能力保留整手牌，不给每张牌永久添加 retain。原生引擎先保留自带 retain 的牌，再保留其余牌，分别保持相对顺序；known_top 推进按这个实际顺序核对，并扣除保留数量。十张容量、Stomp 跨回合费用重置、到期后恢复普通弃牌均已接入。

本批落实了限时赋予整手保留；逐卡赋予 retain 关键字或单回合标记、WellLaidPlans 的回合末选牌、其他 X 费效果和其他能力仍明确拒绝。多选已接入 Purity 的可选数量规则；基础选择 codec 仍支持其他数量约束，但不将未审计卡牌自动开放。

## 统一验证预算

本批只运行一套两轮 smoke，以及双 seed 42／43 各三轮。每轮 126 场、16 更新、batch 64，训练／search 为 8 simulations；network 晋级为 256 场配对验证，最终测试每 seed 150 场。达到三轮停止，不因低增益自动加轮。此预算用于机制与链路验证，不是通用策略质量验收。

```powershell
.venv-az/Scripts/python.exe scripts/prepare_az_selection.py
.venv-az/Scripts/python.exe scripts/run_alphazero_continuous.py --selection --quick --smoke --iterations 3 --output output/az_g1_selection_v1_smoke --workers 8
.venv-az/Scripts/python.exe scripts/run_alphazero_continuous.py --selection --quick --iterations 3 --output output/az_g1_selection_v1_quick --workers 8 --smoke-evidence output/az_g1_selection_v1_smoke/smoke_report.json
```

## 验证阶段发现的多选策略循环

seed 42 第 0 轮候选在验证集晋级，但其 network 超时率为 33/256（12.9%）。这符合既定规则：主要效用与胜率同时改善即可晋级，没有另设超时否决门槛；因此晋级不代表所有行为都改善。

对一场既有验证超时作了只读确定性复现，未变更模型或预算：`sel-validation-181-0-102`，checkpoint `candidate-0.pt`。结果与原记录一致：第 2 回合耗尽 400 次决策，其中 395 次处于 Purity 选择；模型反复选择／取消第一个候选，确认始终合法，末尾确认概率约 0.256，选择同一候选约 0.264。最终己方 HP 37、敌人 HP 66/72、效用 -0.166667。这是该案例的策略循环证据，不是引擎结算卡死；不据一个案例断言所有超时同因。

完整轨迹及模型哈希：`az_selection_timeout_diagnostic.json`。没有强制确认、修改奖励或删除该局；最终超时率另按冻结测试报告。下次训练设计可使用这份验证证据研究如何学会完成多选，不能将三轮机制通过说成多选策略已学好。
