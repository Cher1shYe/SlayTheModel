## 1. 目标与执行优先级

目标是在固定游戏规则版本内，构建能够处理不同卡牌、怪物及其合法组合的 Transformer 策略／价值模型。先实现可扩展的表示、动态动作与训练接口，再扩大机制覆盖和提升策略质量。不能继续依靠每新增几个卡牌 ID 就扩大固定输入向量和策略输出层。

本规格是 `spec.md` 的通用模型路线补充。后续按本规格实施时，优先完成 T0–T3 的通用架构与既有内容闭环；G2.3f 的 Boss 构筑可解性和后续阶段诊断保留为 T4 的难例工作，不作为开始 Transformer 的前置条件。`spec.md`、`spec_0.md`、旧模型和实验记录保留，不追溯修改旧结论。新架构不代表旧 G1–G6 内容里程碑自动完成。

必须分开验收：

1. **接口通用性**：对已实现机制组成的合法卡牌／怪物组合，可以编码状态、列出合法动作并输出策略，不因新 ID 或实体数量变化而修改网络层尺寸。
2. **内容完整性**：固定目标版本内，纳入范围的每张卡牌、每类怪物及依赖机制都经过模拟、公开观察、动作执行和必要重建审计。未实现机制明确返回不支持，不能使用未知标记后假装已经理解。
3. **策略质量**：在未参与训练和模型选择的组合上，具有稳定的胜率、效用和延迟表现，优于预先冻结的适用基线。

第一阶段承诺接口通用性和既有内容正确性；不承诺零样本理解任意未知机制，不保证所有合法构筑都能获胜。最终“任意卡牌和怪物”必须对应明确内容清单、版本及支持率，不能指未定义范围。

## 2. 范围与当前起点

核心范围是战斗内出牌、目标选择、结束回合，以及卡牌引起的单选、多选、生成、抽弃牌和阶段选择。遗物、药水、其他角色资源、召唤单位和 Boss 状态必须预留实体接口，按依赖完整性分批开放；存在尚不支持的依赖时，整场进入拒绝清单。

奖励选卡、商店、地图路线、事件和整局策略不属于首批交付。自然语言卡面可用于人工审计，不作为运行时效果执行器；无需调用外部语言模型来决定卡牌效果。

截至 G2.3e：

- 当前 `sts2_env/az/network.py` 使用卡牌 ID embedding、10 个手牌位置展平、固定 numeric 和 legal mask 拼接的 MLP，输出固定动作 logits 与标量价值。
- 已有公开信息边界、粒子搜索、合法动作约束、Replay、checkpoint、晋级、恢复和结果复算链路，应尽量复用其契约。
- G2.3e 双 seed 各三轮完成，但整体学习增益未通过，聚焦 Boss 仍为零胜。说明扩大模型或更换架构不能替代机制正确性、构筑可解性与训练覆盖。
- 曾出现采集结果堆积导致内存不足。新数据格式必须优先控制实体、动作、Replay 和多进程传输的内存，不能直接把更多稠密数组写进每个决策。

## 3. 必须保持的边界

### 3.1 公开信息

模型只接收 `InformationState` 的公开投影，不接收完整 world、环境种子、隐藏 RNG、未公开抽牌顺序或未公开怪物行动。

已知牌组和弃牌堆可以表示公开多重集；只有规则确实公开的牌顶／底顺序可以使用位置。历史只保存公开事件，且必须保留决策所需的公开持久统计，不能截断历史后丢失能力计数。目标声明应是充分表达公开信息，不是假定模型知道隐藏状态。

如启用搜索，粒子重建必须同步支持相应机制。支持清单分别记录 `engine`、`observation`、`action`、`network`、`belief/search`、`tests` 状态；network 可用而 search 未支持的场景只能进入显式的 network-only 模式，不能悄悄回退。

### 3.2 版本与可重现性

新建模型架构、机制词表、实体 schema、动作 schema、内容清单、奖励、搜索及数据划分版本。checkpoint 记录全部摘要和精确模型配置；恢复时严格校验。

旧 MLP checkpoint 不允许直接装入 Transformer。新模型默认独立初始化；如后续使用蒸馏，必须单独标注教师、来源、可用动作映射与数据划分，不把蒸馏结果称为纯自对弈收益。

network 通过冻结门槛即可晋级；search 保持观察指标，不要求同步提升。奖励仍使用适用内容的已审计版本；新机制需要新奖励定义时另行版本化，不能为新模型临时改分。

## 4. 机制描述与内容注册

建立结构化 `MechanicDescriptor`，由人工审计后的引擎注册表生成，不依赖从卡面文本猜测语义。描述至少包括：

| 对象 | 必须表达的内容 |
|---|---|
| 卡牌 | 类型、基础／当前费用、升级、目标规则、效果序列、条件、次数、倍率、消耗／保留／虚无等标签 |
| 动态卡牌实例 | 当前区域、临时费用、逐卡强化、附着能力、生成来源及公开身份关联 |
| 怪物 | 当前生命／格挡、公开能力、意图结构、多段数量、目标、公开阶段、召唤／复活状态 |
| 能力和触发器 | 所属实体、触发时点、条件、计数、持续期限、叠加规则和效果参数 |
| 战斗状态 | 玩家资源、回合阶段、待处理选择、可选数量、剩余次数与公开持久计数 |

效果表达为有类型的操作与有界结构，例如 `damage(target, amount, hits)`、`draw(count)`、`apply_power(target, kind, stacks)`，支持有序序列、条件、目标引用和公开参数。不能把不同触发时机合并成无序标签。

新 ID 若完全由已支持操作组合，可注册描述并完成一致性测试后复用网络；出现新操作、新状态或新执行语义则进入机制扩展流程。记录未知机制的具体路径，禁止静默丢弃。

ID 不作为核心语义来源。首版以机制描述及动态特征为输入；原始内容 ID 只用于注册、追踪和报告。若后续加入 ID embedding，必须作为独立实验，并提供禁用／未知 ID 对照，检查是否仅记住内容编号。

## 5. Transformer 架构

### 5.1 两级实体编码

采用共享的机制编码器与战斗状态 Transformer：

1. **局部机制编码**：将实体的效果、条件和触发结构转换为机制 token，经共享轻量投影／池化生成语义向量；同一结构在同一参数版本的推理中可缓存。训练时不得误用旧权重缓存。
2. **状态实体编码**：语义向量与动态数值、类型、区域、归属、公开关系特征融合成宽度为 `d_model` 的 token。
3. **状态 Transformer**：Pre-LN encoder，双向 self-attention，FFN 宽度 `4*d_model`、GELU、残差连接。首版训练 dropout=0，便于确定性排查；修改需记录配置。

状态 token 包括全局战斗、玩家、每个敌人／召唤物、卡牌实例或公开等价计数组、能力、待选择对象、必要公开事件摘要。使用 `[STATE]` 汇聚 token 供价值头与动作打分使用。

相同静态牌在公开无序区域且动态属性、身份关系完全等价时允许合并为带数量的 token；手牌、可选择对象、带逐卡状态的实例不能仅按 ID 合并。实例标识用于引用，不把全局分配器整数作为可学习数值。

无序实体不加入任意绝对序号 embedding；有语义的手牌槽、公开序列和效果顺序显式编码。重新排列无序实体并同步重映射引用后，策略应等变、价值应不变。测试必须区分真正无序关系与游戏规则中的位置含义。

### 5.2 动态合法动作评分

移除绑定固定动作总数的线性分类头。环境生成当前候选动作表，每项至少包含：

```text
ActionCandidate {
  action_key, action_type,
  source_ref?, target_refs[], choice_refs[],
  public_parameters, legal
}
```

引用必须解析到当前公开实体，`action_key` 在该状态和动作 schema 下稳定、可审计；不能依赖枚举顺序作为策略偏好。

动作描述投影为 query，读取相应源／目标实体向量，并通过一层共享 cross-attention 读取状态上下文；共享评分 MLP 输出每个动作的一个 logit。动作之间不做 self-attention，避免候选数平方开销，也允许精确分块打分。最后对所有合法候选统一 softmax；不能对每块各自归一化。

结束回合、确认／取消选择等控制动作使用同一打分接口。padding 与非法动作概率严格为零；非终局若没有合法动作必须报错，不能随机 fallback。支持候选重排后按 `action_key` 对齐概率。

### 5.3 组合选择

候选数较小时使用完整合法候选表。涉及组合爆炸的多选，使用显式“选择下一对象／完成选择”的连续微动作，记录已选集合、上下限与完成条件。

微动作只属于规划／选择阶段，不得提前触发原动作效果、消耗资源或推进回合；完成后由引擎原子执行。无序子集采用规范选择顺序，避免同一集合拥有大量等价序列；有序选择保留顺序语义。必须证明可达终态集合与原合法选择完全一致。

引入微动作会改变决策步数及搜索深度，因此单独版本化；分别统计环境动作数和选择微动作数，禁止与旧预算无说明直接比较。

### 5.4 输出与训练目标

策略头输出动态合法动作分布；价值头对 `[STATE]` 做两层 MLP，输出 `tanh` 标量，含义与冻结终局奖励一致。

首版保留原策略交叉熵与价值 MSE，按状态平均；不让候选动作多的状态仅因动作数量而获得更大权重。标签以 `action_key` 对齐，重排、分块、批处理前后语义一致。

额外胜率头、阶段预测头、世界模型或文本预训练不属于首版必需项；后续加入必须有独立实验理由，不能同时引入而无法归因。

## 6. 参数档位

所有档位使用相同机制、实体、动作 schema 和模型接口，只调整 Transformer 深度与宽度，不能通过限制大档／小档内容来制造性能差异。

| 档位 | Encoder 层数 L | d_model | 注意力头数 | FFN 宽度 | 主干权重近似量 | 全模型规划量级 | 用途 |
|---|---:|---:|---:|---:|---:|---:|---|
| XS | 4 | 128 | 4 | 512 | 0.79M | 约1–2M | CPU 调试、契约回归、最低成本闭环 |
| S | 6 | 256 | 8 | 1024 | 4.72M | 约5–7M | 首个正式训练档，优先验证通用架构 |
| M | 8 | 384 | 8 | 1536 | 14.16M | 约15–20M | 覆盖扩大后的容量对照 |
| L | 12 | 512 | 8 | 2048 | 37.75M | 约40–48M | 数据与吞吐充分后的质量实验 |
| XL | 16 | 768 | 12 | 3072 | 113.25M | 约118–135M | 可选大容量研究档，不默认启动 |

这里 M 表示百万参数。主干按标准 attention 和两层 FFN 的主要矩阵估算：`12 * L * d_model²`，未包含偏置、LayerNorm、机制投影、动作 cross-attention 与输出头。全模型为规划区间，不是已测参数量；T1 必须逐档实例化，以 `sum(p.numel())` 写入配置校验报告和 checkpoint，替代估算作为正式数值。

超出规划区间时先解释实际词表和头部开销，不为凑参数量删掉必要输入。层数／宽度／头数是首版固定配置；调整后使用新架构配置摘要。

默认开发 XS、首批三轮训练 S；不同时启动五档训练。M/L/XL 先验证构造、参数计数和资源需求，只有数据覆盖与实际资源足够时才进入训练。档位不是硬件可运行承诺。

资源报告包含参数、梯度、优化器状态、激活、输入 token、候选动作及并发 worker 的总开销。FP32 参数／梯度及 Adam 两个状态仅基础部分约 `16*参数量` 字节，不能拿权重文件大小代替训练内存；混合精度的实际开销需实测。

## 7. 长度、性能与内存

全注意力状态主干的主要复杂度随 token 数平方增长，动态动作读取状态约随动作数×token数增长；参数档位与长度预算必须分别记录。

首版性能测量使用状态 token 长度128/256/512及候选动作32/128/512的合成梯度测试；这些是测量点，不是已支持游戏上限。T0 根据实际支持内容的最坏合法状态确定硬上限，纳入 schema。超出上限必须明确失败并保存公开诊断，禁止静默截断手牌、能力、生成牌或候选动作。

使用按长度分桶、动态 padding、attention mask、动作分块和批量推理。批量推理不得改变搜索随机流或任务对应关系。只有与非分块／串行参考实现等价后，才启用优化路径。

Replay 保存紧凑类型化特征、实体引用和动态动作标签，不保存重复展开的巨大 dense mask。原始审计记录与训练存储可以分层，但必须通过摘要关联并能重建训练输入；记录实际字节／决策、峰值内存、载入吞吐及采样耗时。

延续有界采集、逐场原子提交、非活跃 Replay 释放机制。不得为解决内存问题暗中减少内容、丢弃长对局或更改采样概率。

## 8. 数据、课程与泛化划分

训练配方由能力注册表约束生成，覆盖合法牌组、升级、生命档、遭遇数量与机制组合。随机生成不能仅替换环境 seed，必须改变实际组合，并记录非法配方的拒绝原因。

至少建立以下分开报告的评估集合：

| 集合 | 检验问题 | 隔离要求 |
|---|---|---|
| 既有分布 | 是否保留现有能力 | 新环境种子，匹配冻结内容分布 |
| 未见组合 | 已知机制能否重新组合 | 牌组／遭遇组合签名不进入训练或验证 |
| 未见内容 ID | 能否依靠机制而非编号 | 完整 ID 留出，其机制已在其他训练内容出现 |
| 未见机制 | 是否正确拒绝未知语义 | 作为拒绝与扩展测试，不混入普通胜率 |
| 长状态／多目标／复杂选择 | 接口与策略是否随规模失效 | 按长度、动作数、机制簇分组 |
| Boss 后续阶段 | 是否存在真实学习样本 | 原始完整战斗与阶段诊断分别报告 |

配置冻结训练／验证／最终测试 seed 及配方签名；测试仅在冠军共同冻结后读取。已经查看的测试不能再次声称未见。复用多个档位的固定测试用于一次预注册比较时，不根据中途测试结果选择后续改动。

Boss 从第一阶段自然开始的主指标保留。若加入后续阶段快照，必须来自合法完整轨迹，保存公开历史与重建所需状态，并作为单独课程版本；诊断快照结果不能冒充整场胜率。人工调整生命或牌堆的案例只能作为明确标注的单元测试。

## 9. 训练和实验协议

### 9.1 架构接入顺序

先在与旧模型完全相同的已支持内容上验证 Transformer，再扩大内容。首次比较同时保持奖励、数据配方、搜索版本、预算和晋级规则一致，避免把新增内容收益误认为架构收益。

新 Replay 保存结构化公开输入、动作 key 和策略／价值标签。旧 Replay 缺少完整实体或关系时不能自动升级；只有可无损重建并逐条验证的数据才允许转换，转换产物另存版本及来源摘要。

搜索通过兼容适配层使用动态动作。扩展状态的候选动作表可以不同，必须逐节点重建并按稳定 key 索引；不能假定全树共享固定动作编号。首批旧内容可以用双向映射过渡，但正式通用接口不得依赖4096等固定总动作数。

### 9.2 三轮快速验证

实施文档不等于授权启动训练。后续用户明确要求实验时，默认沿用快速验证约定：

- 先运行 XS 契约／极小更新检查，再运行待实验档 S 的两轮 smoke；S smoke 未通过不得启动 S 正式训练。
- 正式 seeds 42/43，各三轮；环境种子使用新的隔离命名空间。
- 既有180场课程的首批对齐实验，每轮180场、16更新、batch64、训练和search观测8 simulations；network配对验证256场。新泛化集合与规模预算在启动前另行冻结，不能在运行中悄悄扩展。
- 显存／内存不足优先减少 microbatch 并用梯度累积保持有效 batch；若仍不足则停止并报告。不得未经说明改变有效 batch 或升级硬件开销。
- 三轮到达即停止，不因无增益加轮；首次仅验证一个正式参数档，不把五档全部三轮当作默认任务。

小规模三轮验证检查执行、损失、标签、恢复与初步泛化，不作为通用高质量验收。optimizer、学习率、调度、梯度裁剪、精度、更新数及有效 batch 在运行前冻结；首版沿用现有适用值作为起点，不用测试集选超参。

### 9.3 档位比较

后续比较 S/M/L 时，至少报告同训练样本／更新预算下的结果及实际墙钟、设备、推理预算。另可做等计算成本比较，但必须标明其训练量不同。不同档位允许不同 microbatch，只要有效 batch 与目标协议一致。

扩大档位前先检查：机制编码是否无遗漏、未见组合差距、价值误差、动作标签信息量、后续阶段样本和过拟合。小模型失败不是大模型必然成功的证据；不在数据覆盖明显不足时默认启动 XL。

## 10. 测试与验收

### 10.1 工程与内容验收

必须通过以下有行为意义的测试：

- 改变隐藏牌序／RNG而保持公开信息一致，编码及确定性策略一致；搜索不改变原始环境或兄弟粒子。
- 变更无序实体及动作排列后，价值不变、动作概率按引用正确重排；有序效果保持顺序语义。
- padding、动作分块、不同长度混批与逐样本参考一致；非法动作概率为零。
- 合法候选与真实执行一一对应，重复 key／悬空引用／未知机制／长度溢出明确拒绝。
- 复杂选择覆盖完整合法终态集合，确认后正常退出，取消和资源消费符合规则，无重复选择死循环。
- 每个开放机制覆盖引擎、观察、编码、动作、训练标签；启用搜索时还覆盖粒子重建及串并行一致性。
- 有限 loss、反向梯度、更新后参数变化、确定性恢复、checkpoint版本拒绝、Replay校验及中断恢复。
- 五档参数计数可复算；XS/S完成真实混合长度前后向，其余档位运行资源足够的形状检查，不能因无法实测而宣称吞吐合格。

内容支持率分别报告卡牌 ID、怪物遭遇、机制原语及关键交互的已支持／总数和拒绝清单。只覆盖当前白名单时不得标为全内容100%。

### 10.2 三轮工程验收

smoke和正式三轮正常结束、运行工件可复算；无未知机制静默通过、非法动作、异常吞掉、选择死循环。超时必须计入结果并保存案例，不能删除后报成功；快速批次如出现超时，需说明是策略耗尽预算还是引擎／动作错误。

报告每 seed／每轮晋级、network/search分开结果、Boss阶段覆盖、状态长度、动作数、吞吐和内存。工程通过与学习增益通过分开标记，即使零胜也可完成工程交付，不能宣称策略质量通过。

### 10.3 通用质量验收（后续独立任务）

质量实验至少3个训练seed；按机制簇和组合家族构造足量独立配方，并在预注册时确定样本量、主指标、基线与比较次数。不得直接用每层一个样本的bootstrap点区间声称统计显著。

建议质量门槛，在正式质量实验前冻结：

1. 未见组合测试上，network相对适用基线的胜率差95%置信区间下界大于0，同时报告终局效用与保血。
2. 既有分布胜率差区间下界不低于−2个百分点；关键机制组不低于−5个百分点。样本不足不能判通过，阈值变更必须发生在测试前并留痕。
3. Boss、复杂选择、多敌及长状态组不能被总体均值隐藏；无适用强基线或基线也零胜时，补充可解性证据，不能据零差异宣称高质量。
4. 延迟按目标设备分别测network单次和search整步的p50/p95、最坏长度与峰值内存；T0确定部署目标后冻结SLO，不预先虚构硬件性能。

置信区间需反映独立配方、组合家族及训练seed的变化，采用预先固定的分组／分层重采样方案；同一配方多次出现在缓存中不得重复计作独立样本。报告宏平均、微平均及最弱组。胜率和效用均通过预设条件后，才讨论“在已声明范围内效果较好”。

## 11. 分步实施与交付

| 步骤 | 工作 | 完成条件 | 是否默认启动实验 |
|---|---|---|---|
| T0：接口与覆盖审计 | 冻结目标版本，列机制依赖；定义实体、关系、动作key、长度限制与部署需求 | schema草案、支持矩阵、拒绝清单、代表性公开状态夹具齐全 | 否 |
| T1：Transformer核心 | 两级实体编码、共享动态动作头、价值头、五档配置、checkpoint工厂 | XS/S契约与更新测试通过；五档实际参数表；不破坏旧模型加载 | 否 |
| T2：训练／搜索接入 | 新Replay、批处理、动态动作适配、逐节点搜索、恢复、内存与缓存隔离 | 端到端小样本更新及恢复等价，旧内容动作／奖励对齐 | 仅用户授权的短验证 |
| T3：S档既有内容闭环 | 冻结对齐配置和独立测试；两轮smoke＋双seed各三轮 | 训练和测试工件完整、复算通过、如实报告有无增益 | 需用户要求实验 |
| T4：组合扩展与难例 | 机制驱动注册、合法组合生成、复杂选择；纳入G2.3f及自然后期课程 | 已知机制的新ID无需改模型层尺寸；未见组合与ID留出可测 | 每批按授权三轮 |
| T5：档位与质量 | 数据覆盖充分后比较S/M/L，可选XL，独立质量评估 | 成本／效果曲线、基线及分组置信区间、明确支持边界 | 不自动批量启动 |

T0–T2先形成“能对不同合法组合给出动作”的通用基础，T3证明训练链路，T4扩大真正可支持范围，T5证明效果。六个步骤不是六轮训练，也不代表完成T5就支持尚未实现的规则。

首个实施任务应是 **T0＋T1 的最小可审计切片**：用现有已支持战斗生成公开实体状态，完成XS/S动态动作打分和契约测试；不同时改奖励、添加新Boss或启动五档实验。

建议新增模块职责（名称在实施时可按项目结构调整）：`mechanic_registry`、`entity_encoder`、`action_candidates`、`transformer_network`、`model_factory`；继续复用现有协调器、信息边界和工件审计，不建立第二套无法对照的训练系统。

每步交付源码及适用测试、schema／内容矩阵、精确参数表、配置和版本摘要、内存／吞吐实测、原始实验记录、验收结论及下一步。未完成或未测量项明确标注，不将设计描述写成已实现能力。
