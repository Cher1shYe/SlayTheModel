# 本机并发采集测速（2026-10-19）

CPU: Intel Core Ultra X7 358H，16 核 / 16 线程；系统可见内存约 31.55 GiB，启动前可用约 12.17 GiB。使用 CPU 推理，每个推理服务一个 Torch 计算线程。

未启动自进化、更新模型或修改训练入口。此次并发仅由独立测速脚本调度；正式 ALL 入口仍限制单 worker。

## 方法

同一冻结模型、mixed 0.5、每决策 250 ms、每进程连续 2 场；4 个固定配方循环复测，每档使用相同配方多重集。先串行构建，再共用只读的已构建二进制。每个进程单独使用项目、Godot 用户目录、日志、任务和完整战斗缓存，避免原 PowerShell 启动器的共享日志覆盖。

所有返回战斗经过现有来源、状态、动作、奖励验证；仅完整战斗计数。累计 56 场通过，零失败。初始化构建不计入表中端到端时间，启动进程、加载模型、战斗和文件读写计入。资源采样间隔 0.5 s；内存为子进程工作集之和（可能重复计入共享页），CPU 为整机均值，包含其他程序。

## 建议与限制

本机可以先以 8 个并发作为吞吐优先设置；同时使用电脑或更重视固定时间内搜索量时用 4 个。第二组 8 worker 相比 4 worker，战斗吞吐约 1.79 倍、模拟总吞吐约 1.52 倍，但每决策模拟数少约 12%。尚未测试 12/16 worker，也未做长时间热稳定性测试，不把 8 声称为最优上限。

250 ms 是时间限制，并非固定模拟次数，因此各档的搜索路径、决策数和结果可能不同；这里只测工程吞吐，不用于证明策略收益。按第二组外推 296 场：4 worker 约 12.5 分钟，8 worker 约 7 分钟，仅为这 4 种配方的短测估算，不含更新/验证，不能保证覆盖全部遭遇时相同。
