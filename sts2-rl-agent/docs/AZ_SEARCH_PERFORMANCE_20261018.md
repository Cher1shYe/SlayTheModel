# ALL 动态 MCTS 固定状态性能分析

用户要求停止 256 次模拟对照实验后，在同一模型和固定公开状态上分析性能；没有重启训练或战斗对照实验。

## 测量与瓶颈

模型取自 `search_learned_vs_heuristic256_20261018_215108/frozen_model.pt`，对应此前学习者 `update-001-0128.pt`。使用单个 CPU 进程、PyTorch 单线程、确定性算法、搜索种子 123、深度上限 128、关闭探索。状态包括该实验第一个开局、骑士消耗牌升级保存状态、VIGOR 续执行保存状态。

开局 32 次模拟，优化前 cProfile：实体编码 221 次，累计 2.065 秒，占被测搜索 4.149 秒的约 50%；Transformer 推理 33 次，只占约 6%。编码中的公开状态验证、卡牌库存校验、参考卡牌构造重复发生。各函数累计时间存在包含关系，不能相加。剖析器会显著增加运行时间；下列墙钟耗时来自单独的无剖析器运行。

## 改动及结果等价约束

`plan_dynamic` 增加单次搜索内的编码／预测缓存，默认开启；`cache_evaluations=False` 保留原路径供差分验证。缓存最多保留 256 个条目，使用完整公开状态键和合法动作掩码，另用有界对象引用缓存避免重复构造状态键。所有节点仍执行原有候选一致性检查。

同一公开状态复用实体编码、策略先验和值预测；不缓存粒子世界、不复用隐藏状态、不改变随机数调用顺序。缓存不会跨搜索、模型更新或战斗保留。没有改变模拟预算、PUCT、回传、温度、终局评分或三种叶节点评分规则，也没有通过批量推理改变搜索调度。

32 次模拟开局：编码次数 **221 → 33**；无剖析器耗时 **1.562 → 0.992 秒**，约 **1.57 倍**。完整搜索树（含每个结果分支、先验、初始值、访问次数、累计回传值）以及最终动作、策略目标、实际深度完全相同。

256 次模拟的 9 组优化前／后精确对照全部通过：

| 固定状态 | 叶评分 | 优化前（秒） | 优化后（秒） | 加速比 |
|---|---|---:|---:|---:|
| 开局 | learned | 15.757 | 8.439 | 1.87 |
| 开局 | heuristic | 15.800 | 9.579 | 1.65 |
| 开局 | mixed | 14.783 | 10.078 | 1.47 |
| 骑士 | learned | 17.935 | 12.508 | 1.43 |
| 骑士 | heuristic | 18.378 | 12.910 | 1.42 |
| 骑士 | mixed | 17.820 | 12.830 | 1.39 |
| VIGOR | learned | 6.902 | 5.434 | 1.27 |
| VIGOR | heuristic | 6.944 | 5.493 | 1.26 |
| VIGOR | mixed | 7.702 | 5.513 | 1.40 |

上述九组累计搜索耗时比为 **1.47 倍**，耗时减少约 **32.2%**。32 次模拟的开局中网络预测仍为 33 次，因为新节点确实需要不同预测；推理缓存主要消除同一公开状态重复评估（例如深度截断重访），不是跳过必要网络调用。专项测试验证截断重访时调用数减少、树不变，修改模型权重后下一次搜索重新计算。

优化后主要剩余成本是粒子重建、动作执行后的公开状态生成及其中的卡牌校验；当前吞吐不能按旧无网络 MCTS 的每秒数千次模拟估算。这是固定状态单次测量，不是整场吞吐保证。
