### 确认的问题

1. **network 确实一直结束回合**：对已访问的 256 个验证场景重新执行，initial、candidate-0、candidate-1 各 1,131 次动作全部为 end_turn。典型初始开局 end_turn 概率 0.170239，每张 Strike 约 0.16662；贪心逐动作 argmax 将小偏差放大成确定行为。出牌总概率很高不代表某张牌概率高于 end_turn。
2. **旧 MCTS 的访问次数同票规则掩盖 Q**：典型初始开局 end_turn Q=0.04532、Strike Q=0.11365，均访问一次，却因 end_turn 先验高而选择它。修订为 visits → Q → prior；只在新搜索版本生效。
3. **搜索标签弱、更新量很小**：每轮只有 4 次更新 × batch 32，并且候选未晋级后下一轮重新从初始冠军训练，不能当作连续 8 次训练。4 次模拟常小于根节点合法动作数；旧搜索展开叶节点即使用未学好的网络 value。此处属于预算/启动条件限制，不伪称增加了预算。

### 排除的假设及边界

- Replay 6,325 行中有 4,184 次 play、1,847 次 end_turn、92 次 choose、202 次 choose_set。策略标签累计质量为 play 4,124.5、end_turn 1,906.5、choose 92、choose_set 202。标签不是全 end_turn，真实采集中已有伤害和获胜。
- 动作键通过同一合法候选映射送入模拟器，真实攻击可降低敌方 HP；梯度方向测试确认提高指定攻击标签会提高该动作概率；value 标签与实际整场终局奖励逐行一致，更新确实改变权重。
- 未发现动作索引错位、标签符号反转或 optimizer 未更新。采集 policy 仍按 root visits / simulations 监督；低预算访问标签仍可能粗糙，并非只靠同票修复就能保证 network 学会出牌。

## V7：统一公式，明确基准

奖励版本 `risk-terminal-v7`；搜索版本 `dynamic-risk-puct-v2`。

| 结局 | 奖励 |
|---|---|
| 获胜 | 0.9 + 0.1 h |
| 死亡 | −1 |
| 截断/超时 | clip(−0.1 + 0.9 d − 0.55 ℓ − 0.25 max(0,ℓ)² − 0.25 q², −0.8, 0.8) |

- h = 当前 HP / 最大 HP；不再用开局 HP 作为获胜分母。
- d 为有限主要敌人义务的有效 HP 消耗比例。沿用生命周期账本：召唤物不刷进度，复活中的主要敌人保留义务，Boss 所有有限阶段均在分母中，不因阶段切换重复奖励。
- ℓ = clip((H0 − Ht) / max(1,H0), −0.5, 1)。允许净回血，平方项仅惩罚正掉血。
- MCTS 的 H0 固定为本次搜索根节点 HP；所有模拟均从该根开始。环境终局、Replay z 和 network 验收的 H0 为战斗开局 HP。
- q = clip(当前可见敌方下一轮攻击的预计实际 HP 损失 / 当前 HP, 0, 1)。当前 G2.3e 按逐击取整、Strength、玩家 Vulnerable 和全波共享 block 计算；存活次级敌人参与风险，但不参与 d。只读可见意图及公开能力，不猜未来随机意图。此定义不预测玩家未来出牌，也不把卡牌自伤算作敌方攻击。
- 真实获胜/死亡优先于预算耗尽。非终局环境 step 返回 0；伤害只在终局/搜索截断时结算，不逐步重复累加。

V7 在新展开的非终局叶节点或最大搜索深度处用上述截断公式替代网络 value 回传；终局也用同一公式、根 HP 基准。当前没有额外固定长度随机 rollout。网络继续提供策略先验，value head 继续学习实际整场 V7 标签；新版搜索不混入旧 V6 value 或未经定义的加权 value。该语义由新搜索版本绑定。

评估保存 `player_max_hp`、`incoming_risk` 及完整终局公开状态；晋级和 smoke 审计从这些事实重新计算奖励，并核对终局公开状态。新旧奖励/搜索版本不能混入同一 Replay 或 checkpoint 恢复。
