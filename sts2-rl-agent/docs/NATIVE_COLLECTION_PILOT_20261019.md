## 状态、动作和奖励校验

每个决策先从原生权威战斗状态独立捕获一份快照，与持续预测状态导出的特征和合法动作逐字段比较。新快照的局部模拟历史为空，因此其累计决策数来自已执行输入，累计未格挡命中来自原生 `DamageReceivedEntry`，不是复制预测端计数来伪造相等。

每个非终局动作比较完整 native continuation key；终局核对胜负、HP 和模拟器终止状态。只有完整胜利／死亡对局能够进入训练回放，时间上限、异常、未完成战斗不冒充终局标签。

原生动作表会合并语义相同的手牌副本。适配器检查等价动作组完整覆盖，并将原生动作映射成当前网络的 `end_turn` / `play:hand/...` 键，保留每组的代表手牌位置。未访问动作明确计为 0；策略目标严格等于整数根访问次数归一化。单合法动作的访问次数与模拟次数均为 0、策略概率为 1。

当前每个决策重新建立搜索树，避免复用访问次数与新增模拟计数混淆。完整原生搜索根状态仍可重建，未改动 Combat Solver 引擎、ReplayMcts 的 rollout 或游戏语义。此次没有实现公开信息粒子搜索。

终局标签逐场重算并核对当前 Python V7 公式：胜利 `0.9 + 0.1 * hp/max_hp`，死亡 `-1`；不是 rollout 中间截断分数。只在这个无召唤／无阶段转换范围内验证了奖励一致性。

已知跨引擎差异：原生 BYRDONIS swoop 是 17 点伤害，当前 Python 注册表为 16。适配器保留原生 17，不改游戏或 Python 模拟器来假装一致。因此下面是同一原生后端上各策略的配对比较，不是 Python/C# 两个环境的语义等价或同工作量加速比。

## 使用和产物

当前正式 ALL runner 的默认后端未改变。工程入口有上限（最多 24 场、每决策 50～1000 ms），没有正式多轮训练开关：

```powershell
.\.venv-az\Scripts\python.exe scripts/check_native_collection.py `
  --native-repo ../sts2_datacollection/SlayTheModel `
  --game 'D:/Steam/steamapps/common/Slay the Spire 2' `
  --checkpoint '<现有模型路径>' --out 'output/<新目录>' --build --smoke-update
```

`--build` 在首次使用／原生源代码变化后构建正确的 worker。`--smoke-update` 仅执行两步工程更新及恢复验证，省略则只采集、比较、校验和入库。完整对局逐场原子落盘；失败后同源代码／模型／预算／配方用 `--resume` 复用完整结果，仅运行缺失场次。不要在 resume 时随意改变模型或绕过来源检查。续跑默认不执行 smoke 更新；重复指定 `--smoke-update` 会再次执行这两步确定性的工程检查。报告描述当前调用，首次更新检查保存在本轮 `first-run-report.json`。
