# 自进化训练准备修复与验收（2026-10-18）

本轮解决已发现的训练准备缺陷，不扩充内容准入、不启动正式训练、不评估最终留出集。当前支持边界仍为单人 Ironclad、进阶 0、无遗物药水，146 张初始牌及其已接入变体、76 种遭遇；不是任意游戏内容全覆盖。

## 修复内容

| 问题 | 修复后的行为 | 验证方式 |
|---|---|---|
| 配置被 CLI 短预算默认值覆盖、value 权重未进入 loss | 未指定参数统一取冻结配置，报告记录 effective_settings；loss = policy + 0.1 × value | 配置默认／覆盖测试、梯度缩放测试 |
| 主敌召唤被旧生命周期拒绝 | v6 固定初始主敌奖励预算，追加主敌不扩大预算，保留原生终局和移除语义 | 新旧契约隔离、奖励预算与整场诊断 |
| Hex 重建引用旧牌对象、升级或清除后账本不一致 | 绑定当前牌堆实例，保留升级时临时关键词，忽略已经离开牌堆的清理事件 | Hex 对象身份、关键词与账本测试 |
| 新生敌人同回合行动、复活及连续召唤失配 | 记录公开意图行动事件，重建 REATTACH；稳定出生槽位扩至 128，扩展动作仍在 4096 容量内 | 世界／粒子动作一致性、整场诊断 |

## 冻结参数与恢复范围

`az-all-xs-runner-v2`，`initial-primary-budget-v6`。默认 8 轮 × 48 场，每轮 16 次更新，batch 64、MCTS 8、学习率 0.0003、value weight 0.1；训练与验证均为 40 回合／400 决策。

初始基线和 `state.json` 完成后可恢复；此前的初始化失败需换新目录。每轮候选从冠军权重和新的 AdamW 开始，轮内中断恢复完整优化器状态。恢复严格比较源码、配置、协议与有效参数，只允许增加总轮数或调整 worker 数。旧 schema 的 checkpoint／Replay 和 v1 weights-only 输出不能直接复用。

`report.json` 的 `final_validation` 与 `champion_checkpoint` 指向保留冠军，`history` 记录每个候选及晋级结果。采集或验证遇到契约拒绝会停止，不将失败样本丢弃后继续计分。

## 验证证据

本节最终数字与 [机器可读证据](training_readiness_tests.json) 同步。完整源码摘要见证据；MCTS 逐案例结果见 [training_readiness_mcts.json](training_readiness_mcts.json)。

- 开局预检 **384/384 训练配方、64/64 验证配方通过**；它只证明构造／编码可用。
- 最终专项回归 **55/55 通过**，包含整场 MCTS 采集／Replay 重载与更新级恢复；引擎相关回归 **356/356 通过**。
- 整场诊断使用新初始化 XS、MCTS 8、40 回合／400 决策，检查 64 个验证配方和覆盖全部 76 个准入遭遇的固定卡组，共 **140/140 通过、0 拒绝**；不进行梯度更新。
- 更新与恢复测试仅使用临时目录中的最小夹具。工程测试中的少量梯度更新不是正式训练实验。
- 全 AZ 扩大回归覆盖 65 个文件，分三组执行：进程池测试 2,195 通过；普通组 1,000 通过、14 失败、4 错误；旧内容轨迹组 3,173 通过、2 失败。合计 6,368 通过、16 失败、4 错误，另有 8 个子测试通过。完整回归不是全绿。
- 上述 20 项历史失败／错误全部在修复前提交 `90655dc` 的独立导出目录复现：旧 T4 课程快照缺 `exhausted_this_turn`，缺失历史迁移脚本 `migrate_t4_timeout_smoke.py`，旧 EXPANSION_CONTENT 的 Bomb/Fogmog Dazed 账本不一致。原提交对应测试结果是 16 失败、21 通过、4 错误。本轮不重写历史冻结课程或迁移旧训练工件；新 all-content v2 使用独立协议和新输出目录。
- 当前 ALL_CONTENT 下额外检查 Bomb/Fogmog 两种升级状态，完整世界／粒子轨迹一致；旧版本的失败不能当作当前版本已失败，也不能从总回归中隐去。
- 广泛回归之后补充了公开意图 JSON 恢复修复，最终专项复验覆盖该变更及配置、恢复、冠军保留，整场诊断按最终源码重跑。测试工具的嵌套 Windows 进程池问题以串行运行相关测试解决；中断或资源异常的运行不计为通过。

通过有限案例不等于穷尽所有牌组／随机种子组合，胜、负及预算耗尽都可为合法终止。没有新的学习增益或泛化质量结论。历史 v1 短预算诊断仅作历史记录，不能与 v2 整场奖励契约混算。

## 下一步

1. 按 [运行手册](AZ_ALL_XS_RUNBOOK.md) 在新输出目录运行短程 smoke，核对有效参数、有限 loss、无契约拒绝及冠军 checkpoint。
2. smoke 通过后再决定是否启动默认整场预算的正式训练；同时核对磁盘空间与实测吞吐，旧短预算耗时估计不再适用。
3. 正式运行先看完整验证集的冠军增益与遭遇分项。只有明确要求 `--include-test` 且通过相对初始化的验证门槛，才打开最终留出集。
4. 当前内容上的学习闭环稳定后，再单独规划剩余卡牌／怪物机制；本轮不进行扩充。
