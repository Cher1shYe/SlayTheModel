# 原生逐场缓存、续跑与采集测速（2026-10-19）

本轮没有启动自进化、梯度更新或冠军评估。使用同一冻结通用模型、mixed=0.5、250 ms/决策，对同一组 4 个单人固定配方进行两种 worker 分组的完整采集，共 8 场。

## 缓存与恢复

原生后端原本就支持逐场原子落盘：完整轨迹先写 `.tmp`，完成后重命名为 `<scenario_id>.json`。本轮验证并完善进度记录，暴露 `cached_at_start`、`newly_completed`、`pending`、`invalid` 和 `fights_per_worker`；只有通过轨迹合同验证的完整文件计为完成。损坏文件明确报错，不伪装成已完成或静默重采。

缓存 manifest 绑定模型 SHA256、配方列表、模式、搜索预算、协议和代码来源。相同运行续跑时先验证已有完整场次，只发送缺失场次。未完成的那一场需要重采，目前没有任意决策位置的游戏状态恢复。更换模型、配方或语义代码时不自动混用旧缓存。下一轮采集使用新学习者时，也不能把上一轮旧模型的战斗冒充为新采集；旧数据由回放缓冲区保留。

训练入口既有 `all_runner --resume` 仍使用同一输出目录、原配置及原模型状态；无需先启动新训练才能保存采集。缓存目录为 `collection-cache/<轮号>/`，可独立保留。

新增可配置的小批量复用：`backend.fights_per_worker`，默认 1，建议下一次 250 ms 采集设为 2。同一 worker 内连续战斗复用原生进程和驻留推理服务，每场独立重置并保存；不是无限期常驻服务。仍保留 120 秒 watchdog，配置检查限制批量和搜索预算的组合，1000 ms 配 2 场会被拒绝。

```json
{
  "backend": {"budget_ms": 250, "fights_per_worker": 2},
  "search": {"budget": 250, "leaf_mode": "mixed", "value_mix": 0.5}
}
```

这是合并到已有配置的片段，不是完整训练配置。本轮未改动正式训练配置。

## 当前机器实测

配方：GLOBE_HEAD_NORMAL、THE_OBSCURA_NORMAL、升级 SLIMES_WEAK、新种子 FOGMOG_NORMAL。含召唤与选牌路径，模型和种子冻结；搜索按墙钟预算，因此实际动作路线、决策数和模拟次数可不同。

| 指标 | 每 worker 1 场 | 每 worker 2 场 |
|---|---:|---:|
| 完整战斗 | 4 | 4 |
| worker 启动次数 | 4 | 2 |
| 端到端采集耗时 | 45.22 s | 30.36 s |
| 战斗内部耗时合计 | 27.23 s | 21.22 s |
| 有搜索决策的搜索耗时合计 | 24.43 s | 19.38 s |
| 决策数／有搜索决策数 | 106 / 97 | 85 / 77 |
| 有效回传模拟次数 | 3,555 | 3,645 |
| 搜索阶段模拟速度（含叶子推理） | 145.5 次/s | 188.1 次/s |
| 端到端模拟吞吐 | 78.6 次/s | 120.0 次/s |
| 每个有搜索决策平均模拟次数 | 36.6 | 47.3 |
| 端到端平均每场 | 11.31 s | 7.59 s |

搜索耗时不含搜索前的根策略推理；端到端耗时包含原生启动、模型服务加载、重置、编码、战斗执行及缓存验证。一次性准备构建另耗时 14.91 s，未混入两组采集时间。

若机械外推 296 场，仅采集约 55.8 分钟／37.4 分钟；这是四场样本的估算，不能当作全遭遇时长承诺，也不包含训练更新和验证。双场组总耗时较少约 33%，但路线和决策数不同，不能据此声称 MCTS 本体固定提速 1.49 倍。此前用战斗内部耗时估算约 5 秒/场，漏掉了启动等端到端开销。

## 直接恢复证据与测试

- 双场组第一次 worker 已将两场写入缓存后，Python 注入异常；此时进度为完成 2、待采 2。
- 创建全新的后端实例续跑，仅采剩余两场。前两场的文件哈希和修改时间不变。
- 完成后全缓存重读 0.108 秒；worker 启动被测试钩子禁止，返回轨迹一致，四个文件均未改写。
- 单元测试还覆盖同一 worker 批次内“第一场落盘、第二场前失败”，重建后端后只续采第二场；模型变更拒绝、损坏缓存不计完成、非法批量及超预算组合拒绝。
- 81 项相关回归通过（28.46 s），新增长预算批量拒绝测试单独通过（1 项）。合计 82 项，没有因文档更新重复运行。
