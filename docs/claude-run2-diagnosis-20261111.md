## 2. 新发现

### 2.1 火堆选择与血量无关，方向甚至反了

在回血和升级都可选（排除 Dream Catcher、Tiny Mailbox、Stone Humidifier）的 30,187 次火堆中，最后 41 轮：

| 当前 HP | 选回血比例 | 选回血时其概率 |
| --- | ---: | ---: |
| < 30% | 78% | 0.78 |
| 30–50% | 79% | 0.82 |
| 70–90% | 88% | 0.87 |
| 满血 | 87% | 0.88 |

满血时休息的概率比低血时还高。第一轮“任何血量都不回血”，第二轮“任何血量都回血”：**两轮都没学到“取决于血量”的部分**，只是整体偏好换了方向。分组策略头让回血不再消失，但没有让它与血量挂钩。

### 2.2 独立 critic 在线几乎没学到，离线却能学到 3 倍以上

| 留出数据上的解释方差（rollout 230–233，正常结束） | 未来层数 | 未来进幕 |
| --- | ---: | ---: |
| 第二轮在线 critic（19.6M，每轮 4 遍） | 0.085 | −0.161 |
| 同族 5M 网络，离线在 12 个 rollout 上监督训练（最好点） | 0.288 | 0.183 |
| 线性回归（层数、HP、幕） | 0.335 | 0.206 |

- 日志里价值损失对应约 0.4 的批内拟合，但下一批上只有约 0.05：在线 critic 每次只在最新约 2,300 个决策上训练 4 遍，像是“拟合这一批、忘掉上一批”。离线混合多批数据训练就好得多。
- 即使离线训练，最好的预测也只解释约三分之一的方差，离线网络 3 遍后开始过拟合，没超过线性模型。**这局之后能走多远，大部分取决于随机性**（战斗搜索、地图、事件、奖励）。每个决策从整局回报里能分到的信号很弱，这是从零 PPO 学得慢、只学到“不依赖局面的整体偏好”的根本原因。
- 在第一幕 Boss 前（16 层）的状态上，critic 的预测与 HP 相关系数 0.07，实际未来层数与 HP 相关 0.32。

### 2.3 后期数据仍然稀少

两轮合计 16,001 局：约 5,000 局到第二幕，548 局到第三幕，23 局通关。

## 3. 对方向的判断

1. **同意“现有逻辑的 PPO 不够”**。问题不是网络学不动（第一轮模仿测试：监督信号下平稳学到 85%），而是强化学习信号被随机性淹没、critic 在线训练方式不对、后期样本极少。
2. **价值先验有数据支持**：离线监督训练的价值网络明显好于在线 critic。建议 critic 用跨多轮的回放数据训练，并先用两轮归档（约 85 万决策）离线预训练再上线微调。
3. **成对分叉（同随机种子比较两个选择）是去掉运气噪声的有效手段**：第一轮 50 个 Boss 前火堆的分叉，回血 vs 升级 16 胜 1 负（p≈0.0003），而整局回报里同样的信号几乎看不出来。可用于关键决策（火堆、选路、选牌/跳过）生成低噪声的监督目标或优势估计。
4. **DT（回报条件监督）**：骨架（因果历史 Transformer）还在，缺的是“输入目标回报 + 在轨迹上监督训练”。优点是稳定、能用全部 16,000 局；缺点是本游戏结果大部分是运气，DT 会把“运气好的轨迹”里的动作当成好动作（随机环境下 DT 的已知问题），且通关样本只有 23 个。**不建议作为主方法**；可以以“筛选后模仿”（只学走得远的局里的决策）作为策略初始化，再用强化学习微调。
5. **起点课程**（从模型自己打到的第二/三幕开头开始训练）仍是让模型“看到后期”的最直接办法；奖励建议去掉按层奖励，只奖励打过 Boss 和通关。

## 4. 下一步建议（待用户确认）

| 优先 | 改动 | 验收 |
| --- | --- | --- |
| 1 | critic：跨最近约 30 轮的回放缓冲；用两轮归档离线预训练 | 在线 EV（对实际结果）未来层数 ≥ 0.25 |
| 2 | 起点课程：训练中保存第二/三幕开头快照，约一半的局从这些起点开始；验证仍从头 | 第三幕决策占比、通关样本数显著上升 |
| 3 | 奖励：去掉每层奖励，保留打过 Boss（进幕）与通关 | 精英选择率、低血回血率随血量变化 |
| 4 | 小策略网络（5–20M、短历史），同时间更多更新 | 每小时局数、验证成绩 |
| 5（试点） | 成对分叉标签：先在本机为约 1,000 个火堆生成“回血 vs 升级”的分叉结果，检验监督头能否学到血量依赖 | 预测与分叉结果一致率；满血不再休息 |

## 5. 用户选定的第三轮方案（已实施，待训练）

用户选择：保持端到端（不做起点课程），接着第二轮模型继续训练，用离线价值先验，加成对分叉降噪，增加训练量。已实现（代码与测试见 `model/spire_rl/README.md` 第 8 节 2026-11-11 条目）：

| 项 | 实现 |
| --- | --- |
| 接着第二轮训练 | `train --init-checkpoint runs/main-a0-s2/last.pt`：载入策略与 critic 权重，优化器重建，新 run 目录 |
| 价值先验 | `pretrain-critic`：用第二轮归档的真实后续事件离线训练 critic，最后 8 个文件留出评估；`train --critic-prior` 载入 |
| critic 不再“学一批忘一批” | 每次更新的 critic 训练混入最近 12 轮的数据，遍数 4→2 |
| 成对分叉 | 火堆（概率 0.3）、地图（0.05）复制状态，每个选项在相同随机种子下前进至多 2 场战斗或到幕变化，其余由 critic 估计；2 组种子；选项间回报差作为额外策略损失（系数 2） |
| 奖励 | 整轮固定 α=0.5（无档位切换）；分叉需要短期可测的进度信号 |

成本：本机用小策略、真实战斗预算测量，分叉不改变主线对局（同决策数、同层数），总耗时约增加 25–35%（第二轮每次更新 194 秒中，采样 63 秒、训练 122 秒）。10,000 局估计 14–16 小时，以仪表盘 ETA 为准。

验收（与第二轮最后 2,000 局比较）：
- `rest_heal_rate_full_hp` 明显下降、`rest_heal_rate_hp_below_50` 保持较高（火堆按血量决策）；
- `fork_rest_heal_better` 给出分叉判断的回血更好比例，`fork_taken_was_best` 应随训练上升；
- 在线 `value_ev_floors` ≥ 0.25；
- 固定验证种子的到第二/三幕率与通关数。

这是多项同时改动，结果不能归因到单项。

### 启动前补充（Codex，用户确认的小范围修复）

- 本轮 `pretrain-critic` 只读取第二轮 s2；现有启动命令不变。
- 分叉比较记录随每轮 archive 保存（格式 /3，兼容读取旧 /1、/2），含选项、配对种子、事件回报、critic bootstrap 与停止/失败原因，供回收后核查。
- critic 最佳权重比较包含训练前 epoch 0；按留出层数与进幕 EV 合计选择，退步或持平时保留初始权重。报告看 `best_epoch` 与 `improved`。
- `fork_taken_was_best` 改为只看唯一最优的比较，结合 `fork_decisive`（样本数）与 `fork_tie_rate` 判断；`fork_branches` 修为包含每个选项和种子、含失败分支的实际启动数。
- 本机 CPU 35 项测试通过；没有改变网络、MCTS 预算、奖励或分叉损失，GPU 效果仍待训练验证。字段细节见模块 README 第 8 节。
