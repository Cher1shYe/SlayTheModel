# MCTS 失败与未完成路线的进度奖励

2026-10-15，游戏 v0.111.0，本地修改与部署。

## 原因与评分

此前原生 MCTS 的失败模拟统一为 -1，达到深度上限仍未结束统一为 -0.5。Boss 战的模拟大多失败时，打掉很多生命与几乎未造成伤害的动作无法区分。

令 p 为捕获根时存活主怪的净缺血比例（已修正首版将附属怪也计入的问题）：

`p = Σ(maxHP_at_capture - clamp(branchHP, 0, maxHP_at_capture)) / ΣmaxHP_at_capture`

| 模拟结果 | 新奖励 |
| --- | --- |
| 胜利且存活 | 保留 `0.5 + atan((playerHp - entryHp) / 20) / π` |
| 玩家死亡 | `-1 + 0.49 × p`，范围 [-1, -0.51] |
| 存活但未完成 | `-0.5 + 0.49 × p`，范围 [-0.5, -0.01] |

单次模拟的胜利优于未完成，未完成优于死亡；同类结果内按净伤害区分。MCTS 仍聚合多次模拟的均值，不是对所有路线作绝对字典序排序。取消或时间预算中断的模拟仍不回传，避免偏向更快结束的半条路径。

主怪身份与分母在 Capture 时冻结，Restore 和 Promote 保持不变；真正重建树时才重新捕获。不是累计伤害事件，治疗会降低奖励，过量伤害被截断，后续召唤不会通过反复被击杀刷奖励。捕获时已在场的附属敌人也排除；依据原生 `IsPrimaryEnemy` 与模拟器对应的分支判定，不硬编码怪物名单。多个真正主怪仍按最大生命加权计入。挂起选牌尚未结算时使用其父节点的稳定状态，不猜测未来伤害。

评分在主工程 Search/NativeWorker 实现，CombatSolver API 只提供分支状态的派生指标；不修改收集数据的训练标签或原 Beam 策略。

## 首次修改证据（附属怪修正之前）

- `dotnet run --project smoke/SlayTheModel.ReplaySearch.Smoke -c Release` 通过：失败和深度截断均偏好较高伤害，奖励区间保持胜利／生存顺序；原有复用、取消与中断模拟合同通过。
- `scripts/native-worker.ps1 -GameDir <游戏目录>` 构建与原生测试通过。普通战斗 `CULTISTS_NORMAL` 作哨兵，Boss 为 `KAISER_CRAB_BOSS`、`QUEEN_BOSS`。每场先以同根、seed 41、300 ms、深度 1 比较新旧评分，断言旧评分相同、新评分能区分动作。
- 三场选中动作在原生引擎执行后，预测与原生的净缺血比例分别均为 0.0666666667、0.0196078431、0.0133555927；同时完整 continuation key 相等。回放和根提升检查通过。
- 同一动作后根、同 seed、各 2 秒、默认深度 200 的观察：两种 Boss 旧评分的所有首步均值均为 -1；新评分分别约为 [-0.9562, -0.9456]、[-0.9732, -0.9649]。前者首步由防御变为打击；后者首步仍为打击，普通哨兵亦保持打击。动作变化只证明评分影响搜索，不足以证明更优。
- 原生回合推进、烧牌／强化选牌、头槌三种副本组合及 IPC 回归通过。日志保存于 `artifacts/verification/mcts-progress-reward-20261015.txt`（不入 Git）。

这些是无头单步对账与短搜机制验证，未取得玩家原 Boss 局面的同根复现、整场胜率对照或可见游戏性能证据。两个搜索先后在同一进程执行，JIT 与时间预算导致模拟次数不同，不把次数当作性能结论。当时未测试附属怪的奖励应为零，因此预测／原生数值相等没有发现两边同时包含仆从的错误。

## 附属怪与召唤修正

用户指出召唤物也算血的风险后，新增测试在旧源码明确失败：女王的 400 HP 与开场火炬头聚合体的 199 HP 都计入分母，攻击仆从被错误奖励。修正冻结集合为主怪后，原生侧与模拟侧都排除附属敌人，具体判定沿用游戏的主／附属语义；当前模型目录的 `OwnerIsSecondaryEnemy` 标记来源为 `MINION_POWER`。模拟侧使用快照中的有效 Power，避免搜索期间读 live 状态。

通过的原生测试：

- `QUEEN_BOSS`：伤害仆从、受伤后重新捕获、击杀仆从均不增加奖励；女王受伤只除以 400，不能除以 599。仆从死亡后战斗继续，逐步完整 continuation key 相等。
- 原三场短搜重新通过，女王的 8 点伤害正确得到 `8 / 400 = 0.02`。蟹战两个单位均由游戏判为主怪，继续计入，不根据外形或名称误删。
- `OVICOPTER_NORMAL`：实际推进回合召唤结实的卵，攻击、重新捕获后再攻击均不增加进度。
- `FOGMOG_NORMAL`：实际召唤利齿之眼，攻击致死、重新捕获、回合复活、再捕获并攻击均不增加进度。
- `FABRICATOR_NORMAL`：实际召唤守护机器人，攻击、重新捕获后再攻击均不增加进度。
- 后三场每次实际回合推进与攻击都比较完整 continuation key。幻象测试初版错误地假设第一次攻击后仍可立即再次攻击，修正夹具使其先经过真实复活回合；没有放宽对账断言。

复跑：`scripts/native-worker.ps1 -GameDir <游戏目录> -Mode reward-verify`；仅中途召唤为 `-Mode summon-reward-verify`。默认 `verify` 也包含这些测试。日志在 `artifacts/verification/mcts-minion-reward-before-20261015.txt`、`mcts-minion-reward-after-20261015.txt`、`mcts-late-summon-reward-20261015.txt`，不入 Git。

这仍不是所有怪物及阶段的穷举适配证明。特别是死亡后生成新的真正主怪、主怪复活／换阶段、非原版 Mod 的分类与语义，本轮没有逐一验证。固定集合内的主怪血量恢复会降低进度；新身份的真正主怪在下一次完整 Capture 前不加入该集合。这是当前进度启发式的边界，不影响胜负按战斗引擎判定，不能把进度 100% 当作已经获胜。

## 使用

已通过原生 worker 脚本发布到本地 `artifacts/native-host`，游戏 Adapter 配置引用该目录。退出游戏后重新启动两个模组，即使用新 worker。无需修改 MCTS 配置或采集数据。
