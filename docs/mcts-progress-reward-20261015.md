# MCTS 失败与未完成路线的进度奖励

2026-10-15，游戏 v0.111.0，本地修改与部署。

## 原因与评分

此前原生 MCTS 的失败模拟统一为 -1，达到深度上限仍未结束统一为 -0.5。Boss 战的模拟大多失败时，打掉很多生命与几乎未造成伤害的动作无法区分。

令 p 为捕获根时存活敌人的净缺血比例：

`p = Σ(maxHP_at_capture - clamp(branchHP, 0, maxHP_at_capture)) / ΣmaxHP_at_capture`

| 模拟结果 | 新奖励 |
| --- | --- |
| 胜利且存活 | 保留 `0.5 + atan((playerHp - entryHp) / 20) / π` |
| 玩家死亡 | `-1 + 0.49 × p`，范围 [-1, -0.51] |
| 存活但未完成 | `-0.5 + 0.49 × p`，范围 [-0.5, -0.01] |

单次模拟的胜利优于未完成，未完成优于死亡；同类结果内按净伤害区分。MCTS 仍聚合多次模拟的均值，不是对所有路线作绝对字典序排序。取消或时间预算中断的模拟仍不回传，避免偏向更快结束的半条路径。

敌人身份与分母在 Capture 时冻结，Restore 和 Promote 保持不变；真正重建树时才重新捕获。不是累计伤害事件，治疗会降低奖励，过量伤害被截断，后续召唤不会通过反复被击杀刷奖励。捕获时已在场的小怪仍按最大生命加权计入。挂起选牌尚未结算时使用其父节点的稳定状态，不猜测未来伤害。

评分在主工程 Search/NativeWorker 实现，CombatSolver API 只提供分支状态的派生指标；不修改收集数据的训练标签或原 Beam 策略。

## 本轮证据

- `dotnet run --project smoke/SlayTheModel.ReplaySearch.Smoke -c Release` 通过：失败和深度截断均偏好较高伤害，奖励区间保持胜利／生存顺序；原有复用、取消与中断模拟合同通过。
- `scripts/native-worker.ps1 -GameDir <游戏目录>` 构建与原生测试通过。普通战斗 `CULTISTS_NORMAL` 作哨兵，Boss 为 `KAISER_CRAB_BOSS`、`QUEEN_BOSS`。每场先以同根、seed 41、300 ms、深度 1 比较新旧评分，断言旧评分相同、新评分能区分动作。
- 三场选中动作在原生引擎执行后，预测与原生的净缺血比例分别均为 0.0666666667、0.0196078431、0.0133555927；同时完整 continuation key 相等。回放和根提升检查通过。
- 同一动作后根、同 seed、各 2 秒、默认深度 200 的观察：两种 Boss 旧评分的所有首步均值均为 -1；新评分分别约为 [-0.9562, -0.9456]、[-0.9732, -0.9649]。前者首步由防御变为打击；后者首步仍为打击，普通哨兵亦保持打击。动作变化只证明评分影响搜索，不足以证明更优。
- 原生回合推进、烧牌／强化选牌、头槌三种副本组合及 IPC 回归通过。日志保存于 `artifacts/verification/mcts-progress-reward-20261015.txt`（不入 Git）。

这些是无头单步对账与短搜机制验证，未取得玩家原 Boss 局面的同根复现、整场胜率对照或可见游戏性能证据。两个搜索先后在同一进程执行，JIT 与时间预算导致模拟次数不同，不把次数当作性能结论。召唤／治疗的边界来自公式与固定集合设计，本轮未新增完整原生召唤／治疗战斗。

## 使用

已通过原生 worker 脚本发布到本地 `artifacts/native-host`，游戏 Adapter 配置引用该目录。退出游戏后重新启动两个模组，即使用新 worker。无需修改 MCTS 配置或采集数据。
