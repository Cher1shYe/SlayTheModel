# MCTS 失败与未完成路线的进度评分

更新时间：2026-10-15  
游戏版本：`v0.111.0`

这部分只影响 MCTS 搜索内部的 rollout 价值，不写入训练 journal，也不替代
SpireFormer 的整局奖励函数。

## 评分口径

对搜索根捕获的敌人集合，令：

`p = (Σ捕获时最大生命 − Σ模拟末尾剩余生命) / Σ捕获时最大生命`

每个敌人的剩余生命限制在 `[0, 捕获时最大生命]`。普通死亡按 0 计算；复活或
治疗后使用恢复后的终点生命，因此之前获得的缺血进度会减少。同一敌人重复死亡而
最终状态相同，不会重复累计。主怪、仆从以及仍在阵容中等待复活的 0 HP 敌人都计入。

| 模拟结果 | 价值 |
| --- | --- |
| 胜利且存活 | `0.5 + atan((玩家终点生命 − 入场生命) / 20) / π` |
| 玩家死亡 | `-1 + 0.49 × p` |
| 存活但达到深度上限 | `-0.5 + 0.49 × p` |

ReplayMcts 只在模拟结束或达到深度上限时计算一次终点价值，再将同一价值回传给
访问节点。超时或取消的半条模拟仍不回传。胜利价值始终高于未完成路线；存活未完成
路线始终高于失败路线。

## 状态边界

敌人集合和最大生命在每个搜索根捕获时冻结。根恢复和 Promote 不改变分母；模拟中
新出现的敌人要到下一次完整根捕获后才加入。该值是派生搜索启发式，不进入状态键，
胜负仍由原生引擎判定，`p=1` 不代表战斗已经胜利。

## 验证

- ReplaySearch smoke 覆盖失败与深度截断的进度排序，以及胜利/存活/失败的价值带。
- Native worker `reward-verify` 覆盖女王和开场仆从、普通敌人、召唤物和复活对象，
  并逐步比较预测与原生 continuation key。
- 这些夹具验证评分计算和状态一致性，不证明所有怪物、分裂阶段或第三方 Mod 均已
  覆盖，也不证明整局胜率已经提高。
