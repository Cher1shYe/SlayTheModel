# 统一网络设计：局内局外一个网络，本幕 Boss 价值（2026-11-16，Claude 与用户讨论）

状态：**设计，未实现**。第 7 节是开工前需要用户拍板的事；第 8 节是分步实施计划。证据来自 [small-b 诊断](claude-runb-diagnosis-20261116.md)、战斗网络实验（模块 README 第 8 节 2026-11-16 条）和本幕 Boss 价值的离线测试（`artifacts/analysis/claude-bossval-20261116/README.md`）。

## 1. 已经定下的原则（用户 2026-11-16）

1. **一个网络**同时打牌和做局外选择（选路、拿牌、敲牌、火堆、商店、事件、药水）。打牌和抓牌不分开学：这场战斗的结果影响后面的选择，抓到的牌影响后面的战斗。
2. **实体集合**（Set Transformer 的逻辑）：抽牌堆等是无序集合，只有公开已知的顺序（比如被放回牌顶的牌）才带位置。**不要历史窗口**，只看现在和未来。
3. **价值的核心是“本幕 Boss 能不能打过”**，从任意局面预测，包括普通战斗打到一半时。出牌、留药、选牌都按它打分。
4. **跨幕的价值打折，但打折不写进训练标签**：网络老老实实预测各幕的通过率，只在做决策时按跨幕权重 w 组合。
5. **w 的起点**：第一幕 → 第二幕 w₁ = 0.2，第二幕 → 第三幕 w₂ = 0.5。按“后几幕的预测是否可信”的门槛逐步升到 1。
6. **先把 A0 做好**，升阶（A10 两个 Boss、A2 起换幕只回 80%）以后再说。
7. 每次结果拉回后做固定检查（模块 README 第 7.1 节）：只改血量，价值和选择必须跟着变。

## 2. 网络结构

```
实体（局内局外同一套词表）──► 实体编码（类型 + ID + 数值）
                          ──► Set Transformer（全注意力；实体很多时用诱导点）
                          ──► 汇总成局面向量 ─┬─► 价值头（第 3 节）
全局数值行（血量、最大血量、能量、格挡、      │
金币、幕、层、距 Boss 层数…）直接接入 ───────┤
                                            └─► 打分头：每个合法动作 =
                                                动作类型 + 它指向的实体向量 + 局面向量 → 一个分数
```

- **实体**：
  - 局外：牌组、遗物、药水、本幕 Boss（A10 时两个）、地图节点（或“到 Boss 前还剩几个火堆、精英、商店”的摘要）、奖励、商店、事件选项。
  - 战斗中再加：手牌、抽牌堆、弃牌堆、消耗堆、待选牌、怪物、双方能力。
  - 战斗中也要看到局外实体（幕、层、本幕 Boss、地图剩余、牌组），否则无法预测本幕 Boss（离线测试第 3 节；现在的战斗观察只有本场遭遇编号）。
- **打分头**：局内局外通用。“这张牌打这个敌人”“拿这张牌”“走这个节点”“火堆敲这张牌”都是候选。现在的局外网络和战斗网络本来就都是这种指针打分。
- **规模**：先按战斗网络的 1.4M 量级（宽 128、3 层）起步，地图实体多时用诱导点。吞吐比参数量重要（论文：6.6M、无历史、16.6 亿个决策）。

## 3. 价值头

从当前局面（在第 k 幕）出发，网络输出（都不打折）：

| 输出 | 含义 | 训练标签 |
| --- | --- | --- |
| q₀ | 本幕 Boss 打过的概率 | 时序差分与最终结果混合：标签 = (1−λ) × 下一个局面的 q₀ 预测 + λ × 后续的标签，本幕结束时是真实的 0/1。λ 先取 0.9 左右，离线调 |
| q₁ | 假如本幕过了，下一幕也过的概率 | 到下一幕开头那个局面时，取网络自己的 q₀ 作标签（自举） |
| q₂ | 再下一幕也过的概率 | 同理，取下一幕开头那个局面的 q₁ |
| 战斗辅助（只在战斗中） | 这场死不死、打完剩多少血、用掉几瓶药 | 这场打完就知道；只用来帮主干学会看局面，不直接参与决策 |

做决策时的价值：

```
U = q₀ × (1 + w₁ × q₁ × (1 + w₂ × q₂))       （在第一幕）
U = q₀ × (1 + w₂ × q₁)                         （在第二幕）
U = q₀                                          （在第三幕；A10 时 = 两个 Boss 都打过）
```

- w 全为 1 时，U = 预计能过几幕（0–3）。w 小于 1 时，就是用户说的跨幕截断。w 只在使用时出现，改 w 不用重新训练价值头。
- A0 下每幕开头回满血（已核对原生 `AncientEventModel` 与 C++ `events.cpp`），所以血量只影响 q₀；带进下一幕的是牌组、遗物、药水、最大血量、金币，这些通过 q₁、q₂ 体现。
- 离线测试的参考值（简单模型，旧策略的数据）：Boss 前最后一层 q₀ 的 AUC 约 0.86 / 0.83（第一 / 二幕），幕开头约 0.68 / 0.74；牌组是主要预测因素；血量 +10% 使 Boss 前的通过率高约 4 个百分点。新网络应不低于这个水平。

## 4. 价值怎么反馈到打牌和选牌

1. **战斗：网络 + 搜索**（现有 `NetSearch`，每次模拟都重抽隐藏状态，只用公开信息）。叶子估值用 U，打分头给先验。搜索选出的打法再教给打分头，即自我迭代。
   - 数值尺度问题：一场普通战斗内 U 的差别很小。第一版用每棵搜索树内的最小–最大归一化（MuZero 的做法）。若搜索仍分不出好坏，改用“汇率”：用 U 算出 1 点血、1 瓶药值多少，给本场结果加权（第 7 节第 2 项）。
   - 预算：用户给的普通 256、精英 512、Boss 1024 起步；普通战斗可试直接用网络出牌换吞吐。
2. **局外**：两种做法见第 7 节第 3 项。
3. **一致性**：选牌好不好，由同一个网络拿这副牌实际打出来的结果决定。网络打牌变强，同一副牌的价值也随之更新。

## 5. 训练流程（一轮）

1. 自我对弈整局：战斗由网络 + 搜索（带根节点噪声），局外由打分头按概率选；记下所有局面、搜索的访问分布、每场战斗结果、每幕通过与否。
2. 训练：
   - 战斗的打分头学访问分布；
   - 局外的打分头按第 7 节第 3 项的做法学；
   - 价值头按第 3 节的标签学；
   - 只用最近几轮的数据（标签随策略变化）。
3. 固定检查与验收（第 6 节），通过后进入下一轮。按工作日分段，到点保存退出（沿用现有约定）。

## 6. 检查与验收

| 检查 | 方法 | 合格标准 |
| --- | --- | --- |
| 血量敏感度 | 模块 README 第 7.1 节：只改血量 | q₀ 随血量单调变化，量级与受控实验相当；火堆低血时更爱回血 |
| 价值是否准 | 按幕和距 Boss 的远近算 AUC，与离线测试比 | 不低于离线简单模型 |
| 价值是否“排得对” | 归档里 1 万多个火堆分叉（同一局面回血 vs 升级各打下去）：比较 U 的排序与真实结果 | 与分叉结果同方向；这是“能不能帮你做选择”的直接检验，前面的测试都不能代替 |
| 战斗 | 188 场固定战斗成对比较（MCTS 两档、网络、网络 + 搜索） | Boss 死亡率低于 MCTS 128/512 档的 38% |
| 整局 | 200 个固定验证种子 | 超过 small-b 的 25.6 层和第四轮的 29.3 层，到第二、三幕率，通关数 |
| w 升档门槛 | 下一幕开头局面的 q₀ 在留出数据上的 AUC | 达到某个阈值再调高 w（阈值由用户定，建议第一次用 0.7） |

## 7. 开工前需要用户拍板的事

**用户 2026-11-16 的答复**：
- 第 1 项：通关加重，r₃ = 3，即第三幕那一项乘 3。
- 第 3 项：按建议，A 起步，B 先用在火堆和拿牌。
- 第 4 项：战斗从 MCTS 数据模仿起步；价值头从零；局外不从任何旧模型蒸馏，倾向从零（细节见下面第 4 项的补充）。
- 第 5 项：自我对弈用普通 256、精英 512、Boss 1024。
- 第 2 项（解释后）：两种都实现（树内归一化、汇率），在 188 场固定战斗上成对比较后再定。
- 第 4 项补充：局外的价值头先在归档上离线训练 q₀，按建议做。
- 用户：先按此实施，有问题拉回来再改。**2026-11-16 起开始第 8 节第 1 步。**


1. **通关要不要额外加重**：按上面的 U，w 全为 1 时每过一幕算 1 分，通关就是第三幕那 1 分。用户以前定“通关奖励最大”（奖励里通关 5、进幕 0.5）。如果仍要通关远比过前两幕重要，可以把最后一项改成 r₃ × q（比如 r₃ = 3）。
2. **搜索的数值尺度**：先试树内归一化，不行再用汇率（建议），还是直接上汇率。
3. **局外选择怎么学**：
   - A. PPO，价值用新的 U：每个选择的好坏 = 选完后的 U − 选之前的 U。信号短而准，比整局回报好得多。
   - B. 往前看一步：拿牌、敲牌、删牌、火堆回血、丢药这些选择，结果是确定的，不揭示隐藏信息。可以直接算出每个选项之后的局面，用 U 打分，打分头学这个打分，和战斗里“搜索教策略”是同一个逻辑。要注意的是：会揭示隐藏信息的选择（走进问号房、开宝箱）不能这样做，必须只走到公开的局面为止（NoSL）。11-15 的“按选项打分的价值头”在选牌上失败过，所以要用第 6 节的分叉检验盯住。
   - 建议：A 起步，B 先只用在火堆和拿牌，用分叉检验对比两者。
4. **从哪里起步**：
   - 战斗部分：从第 0 代 MCTS 数据（48,642 个决策）模仿起步；
   - 局外部分：从 small-b 蒸馏会继承“不看血量”，建议从第四轮 d3 或 small-b 蒸馏后再让价值头独立训练，或者局外从零开始；
   - 价值头：都从零训练。
   - 补充（局外从零）：可以，论文就是从零训练的，但它用了 16.6 亿个决策，我们的吞吐低两个数量级。从零训练最大的代价是早期局外乱选、局很短，到第二、三幕的样本长期很少，q₁、q₂ 学得慢。建议：**局外策略从零，但价值头先在已有归档上离线训练 q₀**。归档里的标签是“这一局这一幕实际过没过”，是事实，不是旧模型的选择，不会继承旧策略不看血量的问题（离线测试里血量效应清楚）。这样局外策略一开始就有一个大致可信的价值引导，对 A 和 B 两种学法都有用。前提是新的局外实体编码要能从归档里的宏观观察转换过来，设计时保持兼容。
5. **自我对弈的搜索预算**：用户给的普通 256、精英 512、Boss 1024；还是普通战斗只用网络、只在精英和 Boss 搜索，以换吞吐。
