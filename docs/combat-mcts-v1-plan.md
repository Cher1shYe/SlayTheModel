# 第一版全知战斗 MCTS 实施方案

本文记录设计讨论中已确认的范围与行为，是第一版的实现目标，不代表已经实现或验证。

## 已确认的范围

- 固定游戏 v0.111.0，以铁甲战士、无其他玩法 Mod 的单人战斗为首批验证对象。
- 允许使用完整状态，包括牌堆顺序及 RNG 状态；这是全知基线，不代表与玩家同等信息条件下的表现。
- 接管单场战斗中的出牌、目标选择、后续选牌和结束回合；第一版不使用药水。
- 地图、奖励、商店及其他战斗外决策由玩家操作。
- 后续选牌枚举全部合法组合，由搜索决定，不沿用 first-legal 的最低数量选牌策略。若接口区分选择顺序，需要保留合法排列及其语义。

## 目标与模拟策略

- 任何战败劣于任何获胜；获胜方案之间以净掉血量越少越好为目标。
- 净掉血量为入场生命值减结束生命值，允许回血降低损失。复用或重建搜索树时仍保留本场入场生命值作为基准。
- 搜索叶节点通过快速启发式继续模拟，尽量推进至战斗终局；设回合上限避免无限循环。
- 未达到终局的分支不能当作零掉血获胜；超时中断、模拟异常与真实战败分别记录，异常结果不能伪装成有效价值回传。
- 启发式优先可确认的斩杀，其次按敌方预计伤害补防御，再考虑输出；后续选牌使用简单规则。启发式只用于 rollout，真实动作由 MCTS 选择。
- 保留随机 rollout 作为对照，检验启发式偏差。
- 实现时需确定有界价值映射，使战败严格低于获胜，并配套调整 UCT 探索系数；不能直接套用任意血量尺度。

## 时间预算与树复用

- 战斗首次决策搜索 5 秒；后续每步复用已有搜索树，再搜索最多 1 秒。
- 每次只执行一个决策动作；后续选牌同样是独立决策节点。
- 执行动作后，把与真实结果匹配的子节点提升为新根，保留后续统计并释放不再可达的分支。
- 发现实际状态与预测不一致时，以游戏实际状态为准，丢弃旧树、重新捕获状态并搜索 5 秒，然后恢复每步 1 秒。
- 持续模拟异常、不能恢复当前状态或不能处理当前选择时，停止无效重试，暂停并保存诊断信息。
- 时间预算指搜索时间，游戏动画另计。使用单调时钟和可取消的模拟推进；不能等一个无限长 rollout 结束才检查截止时间。
- 预算耗尽时只使用已完成且有效的搜索统计；没有有效根动作时不能盲目提交动作，应报告并进入可手动操作状态。
- 需要分别测量状态捕获、进程通信、恢复、搜索与动作提交耗时；5 秒和 1 秒是目标预算，尚无真实战斗吞吐量或强度保证。

## 原生模拟与进程隔离

优先复用游戏原生战斗逻辑，在独立后台进程中恢复并推进状态，跳过表现与动画。首先验证此路径的可行性，不以手写简化规则替代未验证的原生逻辑。

后台模拟必须满足：

1. 状态复制独立，模拟动作不能改变真实战斗、存档或其他搜索分支。
2. 相同初始状态、动作与 RNG 得到一致结果。
3. 推进至下一个决策点或终局，包括卡牌执行中的选择；不能只识别普通出牌窗口。
4. 不依赖玩家点击或可见选择界面；遇到选择时导出候选项和约束，等待搜索输入。
5. 能中断模拟并回收进程资源，防止卡死占用预算。

已有 JSON 状态捕获、ABI 检查与原生动作桥不等于实现了以上能力。特别需要验证执行中选择的恢复／重放机制、全局单例隔离、遗物及状态计数、随机数流和触发顺序。

## 暂停与恢复

- 提供暂停／恢复热键，具体按键作为可配置实现细节。
- 暂停后不提交新动作；已提交的动作自然结算，尚待处理的选择交回原生手动界面。
- 后台搜索结果带战斗和决策代次，暂停、恢复、换战斗或重建后拒绝旧结果。
- 恢复时重新捕获实际状态、重建搜索树，使用 5 秒预算。
- 在非稳定状态恢复时，先等待可识别的决策点，不强行执行普通出牌动作。

## 开发顺序与验收

### 1. 原生模拟可行性验证

从固定战斗样例开始，实现隔离进程内状态恢复和单步推进。对齐普通出牌、目标、抽牌及随机效果、后续选牌、结束回合和敌方行动。校验语义状态与 RNG；校验失败必须定位差异，不能仅删除不匹配字段。

验收：相同输入可重复，分支之间隔离，真实战斗及存档不被搜索修改，代表性动作结果与实战一致。

### 2. 测量与完整决策接口

补齐中途选择的暂停、枚举及推进；测量状态恢复耗时、每秒推进动作数和完整 rollout 耗时分布，再决定是否需要并行。当前单线程 UCT 不会自动利用多核心。

### 3. 接入战斗 MCTS

增加时间预算、取消机制、启发式 rollout、终局评价、搜索树复用、状态对齐及重建。原有同步 ApplyAction 接口需要适配可暂停选择的原生状态机与进程通信，不能直接在游戏主线程执行整轮搜索。

### 4. 游戏内控制

接入真实动作提交、后续选择、暂停热键、过期结果拒绝及异常诊断。保持 first-legal 为独立联调模式，不将其结果称为 MCTS。

### 5. 效果评估

在同一批未用于调参的战斗起始状态上比较 first-legal、简单启发式和 MCTS：

- 先比较胜率，再比较双方都获胜的战斗中的平均净掉血，并报告共同获胜样本数。
- 记录首次决策、后续决策及重建耗时，包含长尾和超时情况。
- 记录模拟次数、状态推进数、状态偏差、未支持选择、异常及人工接管次数，不能静默排除失败样本。
- 固定游戏版本、程序集哈希、角色、进阶、种子、初始状态、机器及搜索配置。

第一版不预设稳定通关某进阶的要求；先证明正确性，再证明给定时间预算下相对基线的效果。
