# 第二轮训练结果：给 Claude 的简要交接

本文依据已收回的日志和完整 archive，只做结果分析，未修改训练代码或重新评估权重。**请优先依据原始数据独立诊断；下面的排查方向是建议，不是已经确定的根因或必须照搬的修复方案。**

## 1. 结果概览

第二轮 `main-a0-s2` 使用 ruleset v7、宏观观察 v2，约 0.202B 策略网络 + 19.6M 独立 critic。训练 10,000 局、233 次更新、527,686 次决策，归档数量及记录与日志一致。

- 耗时约 11.75 小时；训练中 16 次通关、9,980 次死亡、4 次菜单循环截断，0 次工程异常。
- 已启用分组策略、无档位输入、独立 critic、新 KL 早停和 gate hold；战斗仍是固定 MCTS，普通/精英 128 次、Boss 512 次，没有 Transformer 战斗先验。
- **前期生存改善，但尚无通关能力明显提高的证据；最突出的新偏差是过度休息。**

以下为同一组 200 个验证种子的结果：

| 版本及训练位置 | 平均层数 | 到第二幕 | 到第三幕 | 通关 |
| --- | ---: | ---: | ---: | ---: |
| 第一轮，6,001 局 | 20.81 | 34% | 3% | 0/200 |
| 第二轮，6,021 局 | 20.83 | 44% | 3% | 0/200 |
| 第二轮，8,021 局 | 23.36 | 53% | 8.5% | 1/200 |
| 第二轮，10,000 局 | 22.03 | 49.5% | 7% | 0/200 |

两轮模拟器与训练配置都有变化，这不是单因素对照。0/200 不等于真实胜率为零；1→0 次通关也不足以证明显著退步。第二轮 8k→10k 平均层数下降 1.325，按种子配对 bootstrap 的 95% 区间约为 [-2.68, 0.01]，应继续验证。

## 2. 已确认的现象

**火堆从“几乎只升级”变成了“多数时候睡觉”。** 两轮各自最后 1,000 局，在回血和升级都可选时，回血率从 0% 变成 83.3%。第二轮低于 30% 血量时回血率为 74.0%。更关键的是，按当前模拟器逻辑，排除 Dream Catcher、Tiny Mailbox、Stone Humidifier 的休息收益后，仍有 538 次满血且可升级的火堆选择，其中 460 次睡觉（85.5%）。

具体案例：种子 `1009013`，第 16 层，80/80 HP，只有 BurningBlood、SilverCrucible，存在 16 个升级候选，实际选择睡觉，保存的选择概率约 94.6%。这提供了检查“是否根据血量和牌组条件作决策”的明确入口；不能仅凭回血率高就认定每次回血都错误。

**critic 的长期预测能力仍弱。** 第二轮最后 2,000 局，仅取正常死亡/通关，用归档中的更新前预测对照实际后续回报，层数、进幕、通关分量的解释方差分别约为 0.027、-0.130、-0.059。这与日志中对 GAE 目标计算的 `value_ev_*` 口径不同。稀疏胜例和很小的目标方差会放大负 EV，不能只据某一批的极端负值判断整个网络失效。

**纯通关奖励阶段较短且胜例稀少。** 第 8,217 局才满足门槛、进入 α=0；随后训练 1,783 局，未达到原定 2,000 局要求，`alpha0_requirement_met=false`。这阶段 46 批更新中 41 批没有通关样本。训练正常用完预算，并非再次因 gate 异常停止；奖励切换与后期成绩变化之间的因果关系尚未确认。

**循环污染得到控制。** 4 次训练截断均为删牌网格中选牌与取消预览反复切换，被 64 步保护拦住，没有再出现第一轮近 3,000 步的长循环。第二轮最后 1,000 局的卡牌奖励跳过率约 7.5%，第一轮约 0.65%，稀有动作不再像原先那样完全消失。

## 3. 建议 Claude 优先检查

1. 从上述满血火堆案例入手，核对 HP、遗物、升级候选是否正确进入策略和 critic；检查动作组打分是否过度偏向休息，以及这种偏好是否随局面变化。
2. 用少量真实局面做回血/升级的受控分叉，采用多组独立搜索随机种子，比较即时战损及后续收益；同时检查 critic 的分量目标、归一化与优化效果。先区分输入、目标、优化和探索问题，再决定修哪里。
3. 围绕有证据的问题做小规模对照，再决定奖励课程、网络规模或 MCTS 预算。当前结果尚不能单独支持“模型太大”“搜索预算不足”等根因判断，也不宜直接加入无条件鼓励升级或惩罚睡觉的规则。

期望输出：**数据支持的诊断 → 最小修复方案 → 短实验与验收指标**。验收同时看正常局完成率、按血量/遗物条件统计的火堆行为，以及固定验证种子的层数、进幕率、通关率，不能只看 value loss。
