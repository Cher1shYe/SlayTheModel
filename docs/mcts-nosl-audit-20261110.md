# MCTS NoSL 信息隔离检查

日期：2026-11-10。检查对象：本地 `v111_SF1` / `50d72a6` 的 C++ 模拟器，以及 `model/spire_rl/` 使用的战斗入口。本次仅新增审计样例和交接记录，未修生产源码，未替换 Python 扩展，未改动或重启远端训练，未提交或推送。

## 结论

**未通过严格 NoSL 检查。** 正常路径已经开启隐藏状态重采样，但存在三个可复现的信息隔离缺口。不能再仅凭 `resample_hidden=true` 或旧测试通过，把当前训练战斗器标为“已证明不利用隐藏信息”。

本检查没有测量这些问题对胜率的影响，也不能证明用户远端实验已经遇到相关局面。已观察到的训练进步不因此自动作废；修复前结果应保留，并注明未通过此项审计。

## 用户要求与判据

- NoSL 指不读档悔棋；本项目进一步要求策略不得利用真实隐藏牌序和未来随机数状态。
- 可以使用当前手牌、敌人公开意图、牌堆里有哪些牌及可见实例属性。抽牌堆、弃牌堆等内容默认按无序集合处理。
- 玩家通过已执行的合法操作明确知道的置顶牌可以保留。不能把“引擎知道”误当“玩家知道”；本次已知顶牌测试只检查该字段的保留，不穷尽核验所有写入来源。
- 在模拟中抽到一张假设的牌以后，可以据此作后续模拟决策；在抽到以前，选择器不能读取该模拟的未知牌序。
- 严格回归判据：公开状态、无序牌池和搜索随机种子相同，只改变真实隐藏牌序或隐藏 RNG，采样结果和最终动作应相同。只比较平均胜率或不崩溃不能证明信息隔离。

## 已确认的正确路径

`MacroEnv._advance()` → `RunContext.play_combat_mcts()` → `mcts(..., resample_hidden=true, greedy_rollout=false)`：

1. 搜索复制战斗状态，在每次模拟开始调用 `resample_hidden`。
2. 旧的九个 RNG 流会被搜索种子重新初始化。
3. 搜索节点按公开观察和动作特征分支；当前训练入口使用随机 rollout，不使用读取完整状态的神经网络回调。
4. 汇总模拟结果，只向真实战斗执行一个根动作；不把某条幸运模拟线路作为实际胜利或整段执行方案。
5. 本次普通不同名卡牌对照中，固定搜索种子、反转未知牌序并改变九个旧 RNG 后，24/24 个根动作一致。

这些正确路径不能覆盖下面的新字段遗漏。

## 三个复现问题

### 1. 同名、不同实例属性的牌没有完整规范化

位置：`artifacts/dev/cpp-native-aligned-20261031/simulator/src/battle.cpp` 的 `BattleContext::resample_hidden`，约 345–379 行。

重采样前的排序键只有卡牌 ID、升级、附魔及附魔状态，缺少成长伤害、当前费用、重放次数等实例属性。两张同名、同升级、同附魔但成长值不同的牌会被当成排序相等，固定随机种子仍会从原始隐藏排列产生不同模拟。

复现：手牌相同，抽牌堆仅两张 Thrash，`bonusDamage` 分别为 0 和 30；在两份状态间交换它们，保持 `knownTopCount=0`。公开观察与合法动作特征完全相同。

- 100/100 个相同重采样种子，下一张模拟牌的成长值不同。
- 使用当前训练的普通战斗预算 128、随机 rollout，24 个相同搜索种子中 **5 个根动作不同**。
- 这证明真实隐藏排列影响了有限预算搜索；单凭此结果不推断收益方向或量化作弊获益。

### 2. 公开牌堆编码的排序键漏了新增属性

位置：`simulator/src/observe.cpp` 的 `visible_choice_key`、`push_card_instance` 和公开牌堆排序。

`push_card_instance` 输出 `bonusBlock`、`retainThisTurn`、`slyThisTurn`、`slyThisCombat`，但排序键未覆盖这四项。对于其他属性相同的两张牌，编码可能保留原隐藏次序。MCTS 的 `public_key` 正是调用该公开观察。

本次独立复现了两项：两张 Defend 仅额外格挡不同，以及仅本回合保留状态不同。交换未知抽牌堆位置后，**公开观察向量发生变化**。另外两个 Sly 字段的同类遗漏由源码确认，本次没有单独执行其用例。

这不是玩家应该获得的信息：无序牌堆的内容与属性没变，变化的只有尚未揭示的位置。

### 3. `orbRng` 没有参与重采样

位置：`simulator/include/sts2/battle.h` 的 `orbRng`；`simulator/src/battle.cpp` 的 `resample_hidden`；`simulator/src/defect.cpp` 的 `defect_channel_random`。

新增随机球类型使用 `orbRng`，而 `resample_hidden` 仅重置旧九个流。因此模拟直接继承根状态里这条未来随机序列。

- 两份公开状态相同，仅 `orbRng` 不同的状态，使用相同重采样种子后，该流的下一随机值仍不同。
- 对同一根状态使用 100 个不同重采样种子，下一随机球始终只有 **1 种**结果，而不是在允许的五类球中重新采样。
- 在持有升级 Chaos 的受控战斗状态，24 个相同搜索种子中 **3 个根动作不同**。
- 铁甲通过跨角色生牌拿到相应牌时也可能涉及这条路径；本次未统计远端训练实际出现频率。

另外，`BattleContext::init` 也未显式初始化/接入这条流，当前回到 `Rng(0)` 的默认状态。其与原生随机流的对应关系需要另按原生源码核验，不能只随意换一个种子就宣称规则对齐。
