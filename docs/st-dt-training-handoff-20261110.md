# SlayTheModel：网络训练与奖励设计实施方案

2026-11-10 · v3 · 交给 Claude 的统一实施入口  
状态：设计方案；尚未接入这套训练配置，尚无目标 GPU 的训练吞吐实测。

**本轮采用 0.2B 主模型＋约 1B 对照模型，单卡顺序训练。大档若显存或速度不合适，降到约 0.7B。** 保留此前 ST＋DT 的结构思路，以在线 PPO 从零探索；奖励围绕“活过当前压力、发展后期上限、最终通关”。本文补齐简版省略的设计与实现边界，不恢复 1.5B／2B 的训练安排。

## 1. 任务范围、模型规模与实验预算

| 项目 | 本轮要求 |
| --- | --- |
| 游戏目标 | 固定版本与账号解锁上下文，铁甲 A0 单人完整对局 |
| 网络负责 | 选路、抓牌／跳过、商店、事件、休息／升级及其真实子选择 |
| 战斗负责 | 现有 C++ 环境中的固定 MCTS，首轮不联合训练战斗网络 |
| 初始化 | 两档均随机初始化、全参数训练，无前置示范或预训练模型 |
| 硬件 | 用户提供 RTX 5090、24GB 显存；按单卡预算，启动时核对实际设备 |
| 训练数量 | 每档、每个训练随机种子 10,000 次 episode 启动；失败也计数 |
| 第一轮比较 | 每档先 1 个训练随机种子，两档共 20,000 次训练启动；验证／测试另计 |
| 时间目标 | 争取单档 10,000 局在一天内完成，需包含更新的端到端实测支持 |

“一个模型”包括实体编码、历史编码和各输出头，不是多个场景各训练一个大网络，也不是小 Actor 配大 Critic。最终依据独立胜率、推理成本和训练稳定性选模型，不以参数更多作为成功标准。

常规 FP32 参数、FP32 梯度与 Adam 两份 FP32 动量合计约 16 字节／参数：

| 规模 | 基础训练状态，不含激活等 | 定位 |
| --- | ---: | --- |
| 0.2B | 约 3.2GB | 优先完成学习闭环的主实验 |
| 约 0.7B | 约 11.2GB | 大档备用规模 |
| 约 1B | 约 16GB | 首选规模对照，先实测 |

以上是十进制 GB 的算术估计。1.5B 的同类状态已约 24GB，2B 约 32GB，因此本轮不选。BF16 计算不等于全部训练状态都只有两字节；激活、临时权重、优化器工作区和保存峰值仍需实测。[AdamW 官方说明](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html)

10,000 局是首轮预算，不是收敛保证；此前讨论的 8,000—20,000 局尚未被本项目验证为最优区间。若需要扩大预算，应根据学习曲线另行决定。

## 2. 网络：当前实体关系＋历史决策＋动态候选

### 2.1 为什么保留 ST 和历史 Transformer 两部分

ST 处理当前牌组、遗物、资源和场景之间的关系；历史网络处理此前选择与已经发生的结果。候选头直接读取当前实体，避免把具体目标卡牌的信息全部压进一个局面摘要。

~~~mermaid
flowchart TD
    X["当前公开实体与关系"] --> ST["共享 Set Transformer"]
    ST --> E["实体表示 E_t"]
    ST --> Z["局面摘要 z_t"]
    H["历史状态、实际动作、已获奖励"] --> DT["因果历史 Transformer"]
    G["任务、场景、奖励档位"] --> DT
    Z --> DT
    DT --> C["上下文 h_t"]
    A["当前合法候选与公开属性"] --> CA["候选对实体的交叉注意力"]
    E --> CA
    CA --> P["共享候选打分器"]
    C --> P
    P --> M["合法 mask → 动作分布"]
    C --> V["价值头"]
    C --> AUX["生存、战后 HP、本幕完成预测"]
~~~

五类局外场景共享骨干，通过阶段编码区分。共享参数允许跨场景学习，例如抓牌改变后续选路，金币影响商店选择；但不保证场景之间没有梯度干扰。只有验证发现稳定的负迁移，再考虑小型场景头或 Adapter。

本方案借鉴 [Set Transformer](https://proceedings.mlr.press/v97/lee19d.html) 的集合表示和 [Decision Transformer](https://arxiv.org/abs/2106.01345) 的因果历史结构。由于没有离线数据，首轮用 PPO 在线训练，不将其称为原 DT 或 Online DT 算法的复现。首版不增加五个独立 Actor、MAPPO、RUDDER、MoE 或语言生成头。

### 2.2 ST 输入的实体和关系

| 输入 | 最低信息要求 |
| --- | --- |
| 全局状态 | 当前／最大 HP、金币、角色、难度、幕／层、对象数量、任务与阶段 |
| 卡牌实例 | ID、升级、费用、附魔、成长及其他公开实例属性；重复卡分别保留 |
| 遗物 | 类型、公开计数、已公开的待触发状态 |
| 药水槽 | 槽位、空位、药水类型、公开约束 |
| 地图 | 可见节点、房间类型、坐标、连接关系、可达性、已走路径、已知 Boss |
| 场景 | 奖励候选、库存／价格、事件已知代价、多选上下限、已选对象、能否确认／取消／跳过 |

类别用 Embedding，连续数值归一化后投影；归一化规则随 checkpoint 保存。牌组不加任意排列的位置编码，数量不能因池化而消失。地图可用绑定两端节点的边 token，或关系注意力偏置；节点重排时连接关系同步重排。

实例 UID 用来绑定动作与对象，不把任意 UID 数值当泛化特征。模型只能输入玩家公开可见的信息，不能输入环境种子、真实隐藏牌序、RNG 状态、未来奖励、未揭示房间或事后胜负。

### 2.3 两档网络配置

| 配置 | 0.2B 档 | 约 1B 档 |
| --- | ---: | ---: |
| ST 宽度／层数 | 512／2 个 ISAB | 相同 |
| ST 头数／inducing points／PMA 摘要 | 8／32／1 | 相同 |
| 历史网络宽度／层数 | 1,024／14 | 1,536／32 |
| 历史注意力头数 | 16 | 24 |
| FFN | GELU，隐层为宽度的 4 倍 | 相同 |
| 历史窗口 | 最近 32 个局外决策点，含当前点 | 相同 |
| 归一化／Dropout | Pre-LN／0 | 相同 |
| 动作交叉注意力宽度 | 512 | 512 |
| 估计完整参数量 | 约 0.20B | 约 0.93—1.00B |
| 初始 microbatch | 4 个目标窗口 | 1 个目标窗口 |
| 初始学习率 | 1e-4 | 3e-5 |

ST 摘要投影至历史网络宽度；h_t 投影回动作头宽度，与候选和实体交互。每个候选得到一个 logit，经合法 mask 后 softmax；这些 logits 不是 Q 值。价值头为线性标量，不使用 Tanh 截断。

实际统计全部唯一参数，包括 Embedding、ST、历史主干、动作／价值／辅助头。估计使用单套 Q/K/V 投影，需检查现有 MAB 的重复投影结构。大档本轮控制在 1B 内；备用档将历史层数从 32 降至 24，约 0.7B，重新计数。

## 3. 宏观环境、历史窗口与信息边界

### 3.1 什么算一步

执行一个局外动作，推进到下一个需要局外选择的位置或终局，记作一个宏观转移；中间战斗由固定 MCTS 完成。商店购买与离开、升级行为与选目标、奖励选牌与跳过、多选与确认、满槽换药都保留实际选择，不用随机代选或静默丢弃替代。

环境适配器至少提供：

    DecisionRequest:
      public_observation, phase, selection_context
      candidates[], legal_mask[], request_id

    Transition:
      executed_action, reward_components, next_public_observation
      terminated, truncated, execution_status, failure_reason

候选含动作类型、公开目标属性、价格和必要参数，并保存原始执行描述符。网络选择本次请求的候选索引；执行前校验请求和目标仍有效。非终局无合法候选是错误，终局不调用策略。Padding 不参与任何有效样本的 softmax、熵或损失。

### 3.2 历史的排列和重算

每步按 (g_i, z_i, a_i, r_i) 排列，最多 32×4=128 个 token。预测 a_t 时读取 z_t 位置，只能看到之前动作和已获奖励，不能看到 a_t、r_t 或未来内容。g_i 包含已知任务、阶段及奖励档位。

窗口从最早状态开始，首版不额外带入窗口外前驱动作。每个目标保存 episode_id、step_index、context_start；PPO 重算使用与采样完全相同的窗口、位置索引、候选和条件。跨场景保留历史，跨 episode 清空。

32 步仅限制网络输入，不截断 GAE，也不意味着模型记住整局。更早但仍重要的公开事实需通过当前永久状态表示。首版关闭 KV cache；优化后必须证明窗口语义不变。更新时重新编码原始实体，不能用旧参数的 ST／KV 缓存替代新前向。

### 3.3 分开三种“回报”

| 字段 | 首轮用途 |
| --- | --- |
| realized_rtg | 轨迹结束后反算的实际回报，仅归档或供未来离线实验 |
| requested_return | 首轮为空，不输入数值目标回报 |
| value_target | GAE 产生的价值监督标签，不进入观察 |

在线使用 goal_mode=TASK、task_id=WIN_RUN。Actor／Critic 读取相同公开历史与已知奖励配置，共用一次时序前向；不能把事后实际回报喂给 Critic，让它直接抄答案。

以后若开展自生成数据上的回报条件 DT，应单独定义数值目标、奖励版本及评价方式，隔离实际 RTG 对 Critic 的影响。首轮不要求这个阶段，也不允许把旧轨迹混进当前 PPO 冒充新采样。

## 4. 奖励：当前过渡与未来上限

### 4.1 游戏策略如何通过奖励学习

目标是：在能活过当前威胁的前提下，尽可能发展后续幕和最终 Boss 所需的能力。

- 前期攻击牌可能降低战损，过多暂时无法启动的能力牌可能妨碍过渡；后期又可能需要能力或运转提供数值。不给某类牌永久加分。
- 事件中花血成长、商店删牌与保留金币、绕路拿资源或挑战精英，都由后续生存和通关结果评价，不独立制定行为奖。
- 同样的 HP 在不同牌组、药水和路径下价值不同。低血不必然应该休息，高血也不必然应该升级。
- “休息后打完 Boss 剩余 HP 大于恢复量”是复盘线索，不是反事实证明：若改为升级，战斗路径和风险也可能改变。首轮不据此制作错误动作标签。

因此不按掉血固定扣分，不按回血、金币、抓牌、升级或牌组大小直接加分。过幕回血由目标游戏版本执行，不把讨论中的某个百分比写成新规则。

### 4.2 数值与记账

| 事件 | 初期原始奖励 |
| --- | ---: |
| 首次完成一个新楼层 | +0.05 |
| 首次进入第二幕、第三幕 | 各额外 +0.5 |
| 真实整局通关 | 额外 +5 |
| 正常死亡 | 本步额外 0；前期保留已获得的进度分 |
| 资源变化、取牌／升级、菜单操作 | 直接奖励 0 |

    r_raw = 5 × first_true_run_win
          + alpha × (0.05 × new_completed_floors + 0.5 × new_act_entries)
    r_train = r_raw / 5
    gamma = 1

初期缩放后分别是 0.01、0.1、1。不做单步奖励裁剪，日志保留原始各项与缩放后数值。gamma=1 使真实选择多一次购买或确认，不因多一个时间步就被额外折扣。

楼层奖在房间首次正常完成后发放；同层菜单、多战、恢复快照不能重复领。死亡的战斗不算完成；不同的楼层／过幕／胜利事件可同一步叠加。按稳定的 episode、幕实例和楼层实例身份去重，状态覆盖 clone／保存／恢复；中途起点不补领过去奖励。核验实际楼层上限和特殊路径，不把“50 层”硬编码。

工程崩溃、无效动作和外部超时不是正常死亡；单独记录，不伪造游戏回报。

### 4.3 为什么逐渐取消进度奖励

| 训练启动次数 | alpha | 熵系数 |
| --- | ---: | ---: |
| 1—2,000 | 1.0 | 0.020 |
| 2,001—4,000 | 0.5 | 0.015 |
| 4,001—6,000 | 0.2 | 0.010 |
| 6,001—10,000 | 0 | 0.005 |

永久保留进度分可能偏好稳定爬层却不通关的策略。即使单次通关奖励最大，也不能保证期望总分严格等价于通关概率。前期接受进度作为探索帮助，后期将环境目标收回纯通关；模型选择始终看真实胜率。

每轮 rollout、GAE 与更新冻结同一档位，收完在途对局后切档，记录实际边界；不在局中变奖、不重标旧轨迹。进入第二档前至少到第二幕 1 次；进入纯通关档前至少在 10 个不同训练种子族上真实通关。未满足则停下诊断，不机械降奖或自动加预算。

最终至少有 2,000 个在 alpha=0 时采集、有效正常结束的完整任务训练 episode。若 10,000 次启动内未满足，如实报告，不把局数耗尽当作训练验收通过。上述门槛是初值，不是已经证实的最佳调度。

### 4.4 用辅助预测学习过渡能力

| 预测 | 标签、损失 | 系数 |
| --- | --- | ---: |
| 下一场战斗存活 | 是／否，BCE with logits | 0.05 |
| 下一战结束 HP 比例 | HP／当时最大 HP，sigmoid 输出＋Huber delta=0.1 | 0.02 |
| 当前幕完成 | 是／否，BCE with logits | 0.05 |

下一场指该局外状态后第一场真实普通、精英或 Boss 战斗；HP 在战斗结束后、奖励与过幕回血前记录。若在此之前真实死亡，存活／HP 标签为 0；最后一幕完成要求真实整局胜利。

每个头对有效标签独立取平均；无标签时损失为 0。截断、工程失败或未观察到终点时屏蔽标签，不能补成失败。标签来自自身轨迹，不进入在线输入。

这些头帮助共享表示理解“目前局面能撑多久”，不加入游戏奖励、GAE 或 RTG，也不直接作为候选动作的人工分数。它们预测的是当前策略与固定 MCTS 下的结果，不是与策略无关的客观牌组强度。保留死亡样本，并用关闭辅助头的消融判断收益。

## 5. 从零探索和 PPO 更新

### 5.1 同步闭环

    随机初始化网络和优化器
    冻结本轮行为参数、奖励档位、MCTS 配置
    并行采样至少 2,048 个有效局外转移，再收完在途局
    保存旧动作概率、旧价值、完整公开输入和结果
    计算固定 GAE、价值目标及有效辅助标签
    最多执行 4 个 PPO epochs，按 KL 提前结束
    更新参数版本，开始下一轮；到检查点时独立验证

从第一轮有效数据开始学习，不先收满 10,000 局随机数据再模仿。策略头小尺度初始化，使合法候选初期接近均匀；训练按分布采样，不一直 argmax。首版不加入额外随机动作混合，避免行为概率记错。

有效失败轨迹也进入 PPO；不能只选成功局，不能把失败局每一步都标为错误。旧 log probability 和 V_old 已保存，因此同步系统不必在 GPU 常驻第二套旧策略。更新前先用未变参数核对概率重算。

### 5.2 超参数与损失

| 参数 | 首轮设置 |
| --- | --- |
| 并行环境 | 起步 8 个，根据 CPU、MCTS 和内存调整 |
| 每轮采样 | 至少 2,048 个有效宏观转移，随后收完在途局 |
| PPO clip／epochs／目标 KL | 0.2／最多 4／0.01 |
| gamma／GAE lambda | 1.0／0.99 |
| AdamW | betas=(0.9,0.999)，eps=1e-8，weight decay=0 |
| 一次优化步 batch | 128 个目标时刻，每个带独立的连续历史窗口 |
| 梯度范数上限 | 0.5 |
| 价值损失 | Huber delta=1，系数 0.5 |
| 精度 | BF16 前向／反向；概率、优势及损失统计 FP32 |

学习率见第 2 节。microbatch 控制显存，梯度累积至同样的 128 个有效目标；按样本数正确加权，尾批按实际大小归一化，整次优化步统一裁剪梯度。

    delta_t = r_t + gamma * bootstrap_mask_t * V_old(next) - V_old(t)
    A_t = delta_t + gamma * lambda * trace_mask_t * A_(t+1)
    value_target_t = A_t + V_old(t)

    ratio_t = exp(logpi_new_t - saved_logpi_old_t)
    L_policy = -mean(min(ratio_t * A_t, clip(ratio_t, 0.8, 1.2) * A_t))
    L_total = L_policy + 0.5 * L_value - entropy_coef * entropy
              + 0.05 * L_survival + 0.02 * L_hp + 0.05 * L_act

真死亡／通关的 bootstrap_mask 和 trace_mask 都为 0。可信外部截断取 bootstrap_mask=1、trace_mask=0；不能跨 reset 接到下一局。没有可信末状态的工程失败隔离并报告；反复出现需修复，不能靠丢样本继续制造好结果。

优势与价值目标同轮固定，优势在本轮有效目标上统一归一化，不按场景分别归一化或按胜负重采样。GAE 沿有效轨迹计算，不因 32 步输入窗口截断。记录 KL、clip fraction、熵、价值误差、辅助损失和梯度范数。[PPO](https://arxiv.org/abs/1707.06347)、[GAE](https://arxiv.org/abs/1506.02438) 是方法依据，具体参数仍待实验。

### 5.3 探索停滞和后续数据利用

默认不开课程，先观察楼层、跨幕和真实胜利的信号。楼层分增加但无法过幕时，先查 MCTS 能力、奖励触发、公开状态、候选覆盖和错误率，而不是单纯增加更新次数。

需要课程时，另立配置：正常开局到第 3／5／8 层、第一幕、前两幕，再回到整局。任务在 reset 时固定，达到课程目标是该课程终止，不是整局胜利。可保留约 20% 完整任务用于诊断，再逐渐增加比例；课程局数、目标和奖励单独记账，不替代最终完整任务验收。

积累足够自身成功与失败轨迹后，可以另做回报条件 DT 或自模仿实验；它们不是本轮启动条件。旧数据只能用于明确的独立学习阶段，之后 PPO 需重新采样，不能把额外数据收益归给模型规模。

## 6. 固定 MCTS 与训练资源

### 6.1 战斗执行条件

以现有 hidden_mcts_controller 为接入参考，使用 hidden／resampled 模式；搜索随机流独立于游戏真实随机流，每次只执行当前选择再观察重搜，不能执行某次幸运隐藏状态样本的未来路线。需要核验信息边界，配置名叫 hidden 不等于已经证明无泄漏。

短测初值：普通／精英每次真实决策 128 次模拟，Boss 512 次；与较低或较高预算比较能力与耗时后冻结。不要隐式沿用旧 Boss 10,000 次默认值。搜索探索常数、rollout、药水评分、上限和版本一并保存。

训练与评测、两档模型使用相同战斗条件，不因大网络慢就降低搜索量。MCTS 是固定战斗执行器，不提供局外动作标签；结果代表该执行器下的局外策略能力。

### 6.2 单卡 24GB 的实现方式

优先普通 AdamW、BF16 计算、激活重计算、小 microbatch 和梯度累积。不默认采用 CPU offload，因为主机传输与 CPU 优化还可能挤占 MCTS 资源。若 1B 不合适，先降约 0.7B，而不是为规模增加复杂度。[激活重计算说明](https://docs.pytorch.org/docs/stable/checkpoint.html)

GPU 集中批量推理，CPU 环境不各自复制网络；先同步采样再更新，避免同时竞争显存。按有效长度分桶和 padding mask 减少浪费，但不能截掉真实实体或合法候选。更新时可以优化重复计算，前提是概率重算和梯度语义不变。

测量初始化、反向、首次 optimizer.step 和保存时的峰值；仅前向能跑不算训练通过。尽量保留约 3—4GiB 显存余量，并记录 allocated、reserved、总占用和主机峰值内存。首版先用小形状 FP32 验证正确性，再测 BF16；不通过冻结随机大主干只训练 LoRA 来冒充全参数训练。

## 7. 10,000 局能否一天完成

先做前 200 次训练启动以及至少 10 个完整采样—更新周期，有效训练计入预算。两档分别测；覆盖后期、长牌组、多候选和长局，不能用初期快速死亡的分布外推全部过程。

短测报告包含实际参数、GPU／CPU／RAM、软件版本，以及 MCTS／环境、特征传输、推理、PPO、评测、保存的墙钟时间。同步系统可估算：

    总时间 ≈ 各轮采样墙钟时间之和 + 各轮更新墙钟时间之和
             + 验证 + 测试 + 保存／启动开销

仅训练 10,000 局在一天完成，合计需约 **0.116 局／秒**，即包含更新的 **8.64 秒／局摊销时间**；这不是每个并行环境的单局时限。另有六次各 200 局验证和最终 1,000 局测试，共 2,200 局，需要额外计时。

局数也不等于计算量：例如每局平均 100 个宏观转移，10,000 局约有 100 万转移，4 epochs 最多使用约 400 万个训练目标，每个目标还携带历史与实体。该数字是尺度示例，需以实测的步数和提前停止情况替换。

对完整流程外推并留约 30% 余量。1B 的显存或吞吐不达标则试 0.7B；仍不合适就先完成 0.2B。不得偷偷减少真实选择、MCTS 或更新预算来宣称原实验达标。

当前没有目标 GPU 实测，贪心引擎每秒上百局也不包含本方案成本。一天是预算目标；装得下、跑得完、学得好需要分别验收。两档各一天不等于两档合计一天。

## 8. 评测、数据与恢复

训练／验证／测试按开局种子族隔离，同一开局派生的快照与分支不跨集合。环境、参数初始化、策略采样与 MCTS 的 RNG 分开管理，不作为网络特征。

训练前及约 2k／4k／6k／8k／10k，各用固定独立的 200 个种子验证，按固定评测 RNG 采样动作。主指标为真实通关数／全部评测启动数；另报正常终止样本中的胜率、错误／截断率、幕到达率和原始奖励分项。胜率相同保留原 checkpoint，不用塑形分选胜者。

冻结模型后在另一组 1,000 个种子上测试，报告 95% 区间和两档的成对结果。测试集不参与调参；相同局数之外也比较总耗时。两档使用同一训练开局种子流与搜索预算，各自采集轨迹；学习率不同需披露，不把它称为仅改变参数量的严格消融。

首轮有信号后至少用 3 个训练随机种子复验；额外训练量另计。后续优先做窗口 1 对照、关闭辅助头、纯通关奖励对照，以判断历史和辅助设计是否值得成本，不要求第一天完成全部研究。

保存一次原始公开实体、完整候选／mask、实际动作、旧概率／价值、奖励分项、窗口边界、终止分类与行为版本；窗口按需索引，不重复存储 32 份前缀。当前 PPO buffer 与历史归档分开，旧 buffer 不当新数据使用。

检查点绑定规则／源码／二进制、观察／动作／特征 schema、解锁上下文、MCTS、奖励与归一化。保存模型、优化器、随机数、计数和档位，优先在采样—更新边界恢复；无法恢复中途环境和历史时丢弃残缺 buffer 并记录，不伪称无缝续跑。

仅轮换本实验的最新恢复点、最佳权重和必要里程碑。完整 Adam 恢复文件可达十几 GB，启动前检查磁盘；不覆盖原始参考权重，不复制游戏安装包或整个数据集。
