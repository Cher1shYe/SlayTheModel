# MCTS 与采集器修复

2026-10-15，本地修复，适用游戏 v0.111.0。

## 采集停止

原数据 `fcb5038d6f77493ea3f9f84f1fca92cc` 最后两条为 process_exit 和 collector_error，游戏历史已记录这局结束。旧检查点停在序号 5，而日志已继续到序号 12。续局走检查点不匹配分支时，匿名对象的 `DurableEventSequence` 与 `durable_event_sequence` 经 snake_case 转换后同名，序列化失败并停用采集器。

使用明确的 `ResumeCheckpointMismatch` 记录类型区分检查点与日志序号。续局无法证明连续性时，发布旧的不完整片段，再开新片段；不将缺失内容伪装为完整轨迹。异常详情现在也写入游戏日志和采集诊断。

## 自动操作采集

MCTS 的原生 GameAction 入队不经过人工点击入口，ICardSelector 返回结果也不经过选牌 UI。新增可选模组桥接：动作入队前冻结观察，入队后记录提交；选牌结果返回游戏前记录确切的候选与所选对象。复用执行结果、父动作与嵌套选择的既有协调逻辑；使用 policy 身份，不制造人工点击或网络回执。未装采集器时自动出牌仍可独立使用。

## 头槌选牌

选择 token 的实例序号按卡牌 ID 与升级等级计数，原桥接却按完整状态键计数。混有不同附魔或关键词的同名副本时，第二个实例会查找失败。现按 token 定义定位实例，再严格校验完整状态键，拒绝错误状态和重复实例。

## 验证与边界

- Collector smoke：检查点不匹配诊断可序列化；旧片段发布为 incomplete、value_target_valid=false，后续片段仍可完成。
- Native worker：普通／虚无混合、普通／附魔混合、相同副本的头槌选择与原生 continuation key 对账；保留烧牌、回合推进与 IPC 测试。
- 可选采集集成：设置 `STS2_COLLECTOR_TEST_DLL`，加载构建好的采集器，实际执行自动出牌和头槌选择，检查日志与 coverage gap。
- 此次无头验证不等同于重新完成一整局可见 Steam 游戏。原局缺失的动作无法从游戏历史还原，原始数据保持不变。
