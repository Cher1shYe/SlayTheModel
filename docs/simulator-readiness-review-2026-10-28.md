## 需要优先修复的已确认问题

### 1. 规则错误会让策略利用模拟器漏洞

- **Sword Boomerang 重复计算修正。** `simulator/src/cards_ironclad.cpp:147` 先调用 `calc_player_damage`，再传给内部再次计算修正的 `attack_monster`（`battle.cpp:546`）。同样的 Shrinker Beetle，基础伤害 9；Vajra 提供 +1 力量后应为 12，实测为 15。
- **Mangle 临时减力量恢复符号错误。** `cards_ironclad.cpp:423` 写入负的恢复值，而 `battle.cpp:324` 又把它加到力量上。实测力量 `0 → -10 → -20`。
- **Dark Shackles 没有恢复临时力量。** `cards_colorless.cpp:105` 只扣力量，没有登记恢复。实测 `0 → -9 → -9`。
- **Alchemize 是空实现。** `cards_colorless.cpp:279` 直接返回成功，仍留着 `no potion system` 注释。空槽打出后消耗能量但没有药水，覆盖表仍标 IMPLEMENTED。
- **Boss 条件被错误当成恒真。** `tools/gen_monsters.py:60` 将未知条件映射为 0，`src/monsters.cpp:61` 默认返回 true。Lagavulin Matriarch 的 ASLEEP 判断落入此路径。复现：seed 1234、10 张 Strike、玩家 500 HP，先攻击 Boss（227→221），随后连续结束 6 回合，它始终睡眠、不攻击。高玩家 HP 仅用于观察，未修改源码。其他未知条件也需要逐个检查，不能据此推断所有怪物均错误。

建议先增加有明确前置状态和预期后置状态的效果测试，再修复。未知生成规则应报错或明确标记 unsupported，不能静默当作恒真。

### 2. 训练器会把错误中断当作正常 episode

`agent/selfplay.py:94` 与 `agent/card_train.py:72` 固定选择事件选项 0。STONE_OF_ALL_TIME 在没有药水时只允许选项 1；执行失败后两处直接 break 并返回常规结果。

短测 seeds 1–30：card trainer 在 12/18/23（第 3/5/4 层）提前退出；combat trainer（2 simulations）在 12/18（第 3/5 层）提前退出，均未进入 RUN_OVER。card trainer 还把这些异常终止回报记成 0。

应统一使用合法动作，区分胜利/死亡、步数截断与执行错误；错误样本不得默默进入训练。评估必须报告异常终止率。

### 3. 观测和动作编码不足以支持完整决策

- `bindings.cpp:367` 的 `observe_public()` 在战斗中仍只返回 run 摘要，实际没有文档声称的战斗可见状态。打出一张牌后，该观测可以完全不变。
- `src/observe.cpp` 的 run 编码没有地图、遗物/计数、药水等策略输入；独立的 61 维 combat 编码没有整手牌组成、怪物身份、大多数 powers 等信息。合法动作的逐个卡牌特征不能替代完整的状态输入。
- `combat_action_features` 只编码前 4 类动作，没有独立编码第 5 类 USE_POTION，也没有药水 ID。实测同一状态分别携带 BlockPotion / EnergyPotion，state 和药水 action features 完全相同。
- CHOOSE 仅在手牌里按 uid 查卡，来自抽牌堆、弃牌堆、生成候选的选择不能得到完整候选特征。

需要一套版本化的公开观测和候选动作编码，覆盖所有实际决策对象，同时继续排除 RNG 和未来抽牌顺序。策略只能基于拿到的信息学习。

### 4. 当前搜索与真实游戏可用信息存在差距

`src/search.cpp:96` 实现的是根动作 UCB/PUCT 分配加贪心整场 rollout，没有多层树展开与逐层回传。它可以作为基线，但不是完整的多层 MCTS。`agent/selfplay.py:59` 算出的 value 被丢弃，没有参与搜索叶节点评估。

`search.cpp:130` 直接复制完整 BattleContext，包括真实抽牌顺序和 RNG，再向前模拟。当前搜索由此利用了玩家未知的未来信息。必须区分这种 oracle 搜索与可部署策略的评估；若要模拟实战可用搜索，应对隐藏信息进行条件重采样或采用信息集方法。

两个训练模块也没有形成统一策略：combat trainer 固定拿第 1 张卡、走第 1 条路、离开商店；card trainer 的战斗使用贪心。地图、事件、商店、休息等仍需要适当策略接口和训练/评估，而不仅是跑通流程。

## 验证和内容缺口

### 覆盖表需要与验证证据分开

`tools/gen_coverage.py:53` 把所有非多人卡直接标 IMPLEMENTED；82 行按掉落池标药水；109 行直接标全部怪物；`src/relics.cpp:58` 对整个 EVENT 遗物池返回 true。这与文档承认部分事件遗物无效果/近似的情况不一致。

`tests/test_smoke.py:368` 的卡牌遍历主要验证不崩和执行成功，没有确认目标效果正确；遗物测试主要验证战斗能结束。地图 golden 和同种子回放能防止回归，但没有带来源的真实游戏逐步状态轨迹，不能独立证明保真。

怪物生成还存在系统性风险：`dump_monsters.py:218` 默认仅采 12 个种子；265–266 行用样本最小/最大 HP 推断区间；281 行用样本频数记录阵容权重；284 行开始只记录每招式的一次效果。动态条件、计数器、阶段和分布需要独立验收。

建议覆盖状态至少区分：有数据、可执行、效果测试通过、参考轨迹对齐；每项关联对应测试与参考来源。

### 三幕流程仍有明确近似

按项目自己定义的 v0.111.0 / Ironclad / A0 / 单人合同：

- 47 个事件只有 3 个 IMPLEMENTED、15 个 APPROXIMATE、29 个排除。
- 第 2/3 幕 Ancient 被跳过。
- 诅咒、附魔/卡牌选择、部分事件遗物效果没有完整建模。
- 排除未实现内容会改变事件、遗物和路线的分布。

其他角色、其他难度和第 4 幕属于当前合同之外，不能混为此范围内的 bug。先做可信的窄范围训练是合理选择，但验收和宣传应明确这个范围。

## 当前模型与评估证据

现存 smoke 结果只用 2 个评估种子，全部 0 胜；不能据此证明当前模型学得更强。四个现成权重路径实际载入现模型失败：

另 `deployment/selfplay_compare.py:39` 把 b=None 描述为 greedy baseline，实际创建随机初始化网络。需要固定独立评估 seeds，分开比较真正的 heuristic、纯网络、带搜索网络，记录分幕到达率、胜率、异常率、失血和样本吞吐，并给出统计不确定性。

## 性能指标与下一步

`deployment/benchmark_speed.py:63` 的 bench_mcts 初始化仍在 Neow，却直接 MOVE；失败后对空战斗搜索，实际 simulations=0，报表按请求次数计速。复现 bench_mcts(64,20) 可报告约 8649 万 sims/s，但没有真正执行模拟。这一指标应停用并修正；原生 bench 的战斗测量不受这个 Python 初始化问题影响。

`bindings.cpp:253` 的 search/search_priors 本身未释放 GIL。clone/rollout 释放 GIL 不能证明当前搜索入口可多线程扩展，本次 RunEnv 多线程结果也没有加速。

建议顺序：

1. 修上述规则错误、非法动作提前退出和无效基准；为每个问题加效果/终止条件回归测试。
2. 建可信参考轨迹差分，优先伤害与状态时序、Boss 阶段、关键卡/遗物组合；同步修覆盖口径。
3. 完整编码公开状态与候选动作，区分 oracle 和可实战搜索；打通战斗与选卡策略，重新生成版本匹配的 checkpoint。
4. 在独立多种子评估中证明当前模型稳定超过明确基线，再扩大事件/Ancient/诅咒等内容。
5. 根据真实训练负载优化地图初始化、进程或原生批处理、批量推理及 GIL 释放；同时报告环境步/s、有效训练样本/s和局长。

当前不需要先堆 GPU 或追求更高的卡牌计数。最有价值的下一步是让现有内容和训练样本可信。
