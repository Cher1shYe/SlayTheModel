# 第四轮（small-a0-d1 至 d3）诊断与修复

2026-11-14，Claude。数据：`runs/training-review/small-a0-d{1,2,3}/`（三段共 7,769 局，约 9.7 小时）。分析脚本和输出：`artifacts/analysis/claude-run4-20261114/`。修复的实现记录见 `model/spire_rl/README.md` 第 8 节同日条目。

## 1. 结论

- 成绩在第一段开头涨了约 6–7 层，之后两段半没有再涨，第三段训练中的平均层数还略降。
- 涨的部分是“不再乱来”（不再丢下金币遗物、不再丢药水），不是新策略。
- 没再涨的主要原因是**分叉损失的写法没有上限**：它把策略推成几乎完全确定，之后主线样本的梯度消失、不再探索，每次更新走不到一遍数据就被 KL 检查拦停。
- 次要原因：学习率偏大；分叉标签噪声大且每个只用一次；PPO 的优势信号大部分是“这局有没有通关”。
- 战斗这堵墙没有变：到第一幕 Boss 的约 25% 死在那，第二幕 Boss 约 45%，第三幕 Boss 约 70%。

## 4. 原因

### 4.1 分叉损失没有上限（已确认）

原写法：对每个被比较的选项计 `−优势 × log P(选项)`。对分数求导是常数（等于负的优势），选项的概率已经多小都一样推。

在四个检查点上直接量到的值（`grad_exp.py`，本机 CPU，重算检查与存档一致到 1e-4）：

| 检查点 | 火堆 log P(升级) | 选牌分叉里最低的选项 | 地图分叉里最低的选项 |
| --- | ---: | ---: | ---: |
| d1 `best.pt`（2,002 局） | −19 | −437 | −53 |
| d1 `last.pt`（3,039 局） | −38 | −34 | −659 |
| d2 `last.pt`（5,340 局） | −168 | −194 | −1,500 |
| d3 `last.pt`（7,769 局） | −539 | −5,181 | −5,033 |

- 火堆的值在所有血量下相同（d3 末从 −539.7 到 −537.4）：学到的是无条件回血。
- 除分叉项外，没有别的损失能把一个没被采到的选项推到这么低：PPO 项和熵项对它的梯度随它的概率一起趋近于零。
- 各项的梯度范数（d3 末，128 个样本的小批）：分叉项平均 156，PPO 项 2.3，熵项 0.13。d1 `best.pt` 上含两个选牌分叉的小批：分叉项 530，PPO 项 64。

### 4.2 饱和之后 PPO 基本失效（较强怀疑，机制成立）

被选动作的概率到 1 时，它对分数的梯度趋近于零，别的选项也不再被采到。剩下只有分叉项在推，偶尔把别的局面上的决策整个翻掉，于是每次更新都在几步内被拦停。d3 训练平均层数比 d2 低 1.15 层（约 3.6 倍标准误），与此一致，但没有做对照实验。

### 4.3 学习率偏大（已确认是因素之一，不是单独原因）

- d1 开头预热到 1e-5 至 4e-5 时每次更新能走满 3 遍；到 1e-4 后先是 16–32 步，策略变尖后 8 步以内。
- 第二轮（0.2B，3e-5）平均 1.5 遍。
- 但 d2 第 1 次更新在 1e-5 下仍被拦停（小批 KL 0.35）：饱和之后只降学习率不够。

### 4.4 分叉标签噪声大、用得少（已确认）

同一个分叉两套种子之间，选项回报（去均值后）的相关，以及由此得到的“两套种子的均值”的可靠度：

| 界面 | 分叉数 | 两套种子的相关 | 均值的可靠度 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 地图 | 3,139 | 0.61 | 0.76 | 可用 |
| 火堆 | 10,622 | 0.23 | 0.37 | 约六成是噪声 |
| 选牌 | 4,836 | 0.16 | 0.28 | 约七成是噪声；49% 的分叉里有的分支死了有的没死，方差几乎全来自这里 |

策略选的选项在分叉里的相对回报（以标准差为单位）三段没有上升：火堆 +0.14 / +0.18 / +0.14，地图 +0.17 / +0.13 / +0.16，选牌 +0.05 / +0.04 / +0.01。

火堆分叉按血量看（回血减升级；分支只跑两场战斗）：

| 血量 | 分叉数 | 分支死亡率之差 | 策略回血的比例 |
| --- | ---: | ---: | ---: |
| <30% | 566 | −22.2 个百分点 | 99.8% |
| 30–50% | 1,094 | −19.4 | 99.5% |
| 50–70% | 1,890 | −17.1 | 99.8% |
| 70–90% | 3,052 | −6.3 | 99.8% |
| 90–100% | 1,603 | −0.2 | 99.9% |
| 满血 | 2,417 | +1.7（标准误 0.4） | 99.8% |

血量 90% 以下回血明显更好；满血时升级略好。策略没有分出来。

### 4.5 PPO 的优势大部分是通关的运气（已确认）

- 回报方差里通关项占约 70%（层数项约 8%，进幕项约 3%）。
- critic 对层数的解释方差 0.25–0.36、对进幕 0.15–0.29，已接近离线上限；对通关约 0–0.1。合成标量后解释方差只有 0–0.07。
- 有通关的那 37% 的批里，通关局占 7% 的样本、78% 的优势方差，归一后的优势平均 +3.0。

通关奖励的权重是用户定的，这次没有改。

### 4.6 火堆分叉的视野偏向回血（较强怀疑）

分支只跑两场战斗，其余靠 critic 估。回血的好处两场之内就体现，升级的好处在更后面，而 critic 分辨不出一张牌升没升级（同一分叉两个都没死的分支，估值只差约 0.001）。这次没有改。

## 5. 2026-11-14 的改动

| 改动 | 内容 |
| --- | --- |
| 分叉损失 | 改成“目标分布到策略”的 KL：目标 ∝ max(更新开始时的概率, 0.01) × exp(归一后的优势，限幅 ±3)。推力与选项的概率成正比，达到目标后为零；被推到 0.01 以下的选项会被拉回来 |
| 分叉数据复用 | 每次更新同时用最近 4 轮的分叉决策（优势沿用，目标按当前策略重算）；每步固定带一份分叉样本，走完一遍数据也走完一遍分叉 |
| KL 超限退回 | 发现超限时，把权重恢复到越界那一步之前；更新结束后在固定样本上再量一次保留下来的策略 |
| 学习率 | `small` 预设 1e-4 → 3e-5；一次更新不到一遍就被拦停，后面的学习率乘 0.7（不低于基础值的 0.1 倍）；走满全部遍数则乘 1.1（不超过基础值） |
| 新监控 | `fork_option_logp_min`、`fork_pool`、`kl_rollback`、`sampled_kl_final`、`lr_adapt_next` |

没有改：通关奖励权重、优势的限幅、火堆分叉的视野、奖励界面的熵奖励、种子数。

本机验证：60 项测试通过；在 d1 `best.pt`（已饱和）和第 67 轮真实数据上跑一次新的更新，裁剪前梯度范数 23（原来含选牌分叉的小批是 500 以上），第 9 个小批越界后退回，保留下来的策略在固定样本上的 KL 为 0.004。**没有在 GPU 上跑过，也没有在未饱和的蒸馏策略上验证过**（本机没有 `runs/distill-small.pt`）。

## 6. 下一轮怎么判断

从 `runs/distill-small.pt` 重新开始。d1–d3 的检查点（包括 d1 的 `best.pt`）都已饱和，不建议接着训练。

前 2,000–3,000 局应看到：

- `target_passes` 多数在 1 以上；`fork_option_logp_min` 保持在约 −12 以上（第四轮是 −19 到 −5,000）。
- 火堆回血率随血量不同：`rest_heal_rate_hp_below_50` 高，`rest_heal_rate_full_hp` 明显低于它。
- `fork_rest_taken_was_best`、`fork_map_taken_was_best` 上升。（选牌分叉从下一轮起关闭，见第 7 节。）
- 验证成绩先回到 28–29 层（第四轮靠变尖在约 300 局内到了这里；学习率降低后会慢一些），然后要看能否超过 29.3。

如果训练过程正常（上面前三条满足）而成绩仍停在 29 层左右，说明问题不在更新的稳定性上，下一步该看的是信号本身和战斗。按选项打分的价值头已经在第四轮数据上离线测过，结果是否定的（第 7 节），剩下的方向是战斗网络和网络结构本身。

## 7. 缺口 1（按选项打分的价值头）的离线测试（2026-11-15）

目的：同学在[训练缺口文档第 2.1 节](claude-training-gaps-and-mcts-plan-20261110.md#21-四个训练缺口论文思路与后续实验)提的第一条，“对具体候选的条件价值”。想法是在网络上加一个给每个选项打分的头，用分叉结果训练；如果它对没见过的分叉预测得准，就用它的预测代替单次分叉的噪声结果去教策略，还能用到没分叉的决策上。上线前先在第四轮的数据上离线检验。

做法（脚本 `artifacts/analysis/claude-run4-20261114/optval_extract.py`、`optval_fit.py`、`optval_cardid.py`，结果在同目录 `optval/`）：

- 第四轮三段全部 18,597 个完整分叉。用 d1 `best.pt` 跑一遍，取出每个分叉决策的查询向量和各选项的候选向量（策略打分用的就是这两个），冻结不动。
- 在上面训练岭回归和小 MLP，预测各选项去均值后的回报；5 折交叉验证，按游戏种子分折（测的是没见过的局）。
- 判断标准：每个分叉有两套种子，是两次独立测量。“预测和第二套的相关 ÷ √(两套之间的相关)”就是预测和真实值的相关，可以直接和现在用的“两套平均”比。另放三个对照：策略自己的对数概率；火堆只用血量；选牌只用卡牌 ID（不经过网络）。

结果（与真实值的相关，越高越好）：

| 界面 | 现在用的两套平均 | 打分头（岭回归 / MLP） | 策略自己的偏好 | 其他对照 |
| --- | ---: | ---: | ---: | --- |
| 火堆（10,622） | 0.61 | 0.27 / 0.23 | 0.25 | 只用血量 0.35 |
| 选牌（4,836） | 0.53 | 0.04 / 0.03 | 0.02 | 只用卡牌 ID 0.04 |
| 地图（3,139） | 0.87 | 0.23 / 0.20 | 0.18 | |

把打分头的预测按比例混进分叉结果，按第二套种子检验：火堆最多从 0.225 到 0.240（混 25%），选牌和地图只会变差。

结论：

- **已确认：在这份数据上，打分头不能代替分叉结果，也几乎不能补充它。不接入网络。** 局限：特征来自冻结的、已饱和的 d1 策略；和网络一起训练的头可能学到更多。但选牌上连不经过网络的“只用卡牌 ID”也是 0.04（最好和最差的牌只差 ±0.01 个标准差），说明不是特征的问题：在本幕之内，选哪张牌对结果的影响小到四千多个分叉也测不出规律。选牌分叉里 40% 所有选项结果完全相同。
- **已确认：选牌分叉很贵。** 抽样 1,539 局：分叉里的战斗，火堆占 31%、选牌 58%、地图 12%；分支决策数选牌占 64%。按“分叉战斗约是主线 2.3 倍”算，选牌分叉约占全部模拟器战斗的 40%。
- 火堆的规律主要是血量（只用血量就有 0.35），这正是第四轮策略没学会的（满血也 100% 回血）。新的分叉损失不再把策略推死，这一点应该能学到；看 `rest_heal_rate_full_hp`。
- 两套种子之间的一致程度在各段之间波动大（火堆 d1 0.29、d2 0.07、d3 0.31；选牌 0.23 / 0.17 / 0.07），标签本身不稳定。

因此下一轮**关掉选牌分叉**（`--fork-card 0`），火堆、地图分叉不变。预计每局时间明显缩短（没有实测；看 `seconds_per_episode`，第四轮 4.4–4.7 秒），同样的时间能多跑不少局。选牌从此只靠 PPO 本身学，第四轮的选牌分叉也没有带来可测的改进（策略选择与分叉结果的吻合三段都等于随机）。
